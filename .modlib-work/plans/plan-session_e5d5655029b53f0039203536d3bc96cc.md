## 修复目标
修复 `agent-desktop 1.0.2` 在 macOS 上将 `Chrome` 与 `Google Chrome` 误判为不同应用的问题，并避免修复及后续操作抢占你的鼠标、键盘和浏览器焦点。

## 已确认的原因
- 上游源码 `crates/macos/src/tree/resolve/resolve_source_app.rs` 在应用 AXTitle 不匹配时直接失败，与你遇到的 `expected_app: Google Chrome / actual_app: Chrome` 完全吻合。
- 上游 PR [#419](https://github.com/vercel-labs/agent-desktop/pull/419) 已提供针对性补丁，但尚未合并；npm 最新版本仍是 1.0.2，单纯重装无效。
- 前台干扰来自我使用了 `launch --activate`、`--headed` 及系统级快捷键，不是登录问题。名称补丁本身不能让所有桌面操作变成后台操作。

## 实施步骤
1. **建立独立修复目录并记录原版**
   - 不修改当前 notes 仓库，也不修改 Modlib Work 应用或账号数据。
   - 在用户级工具目录保存源码、版本信息及原安装备份；锁定官方 v1.0.2 对应源码。
2. **应用最小源码补丁**
   - AXTitle 精确匹配时继续直接通过。
   - AXTitle 不匹配时，核对已验证的同一进程 PID 对应的系统窗口 owner 名称。
   - 保留进程实例校验，不改为模糊名称匹配，不允许跨进程命中。
   - 增加 Chrome/Google Chrome 别名、错误进程、缺失窗口清单和读取错误的回归测试。
3. **测试与构建**
   - 检查本机构建环境，使用 Rust 与 macOS 编译工具构建 CLI 和配套 helper。
   - 运行相关单元测试及 core/macOS 适用测试；不运行发送真实键鼠或更改网页的测试。
   - 若构建或测试失败，保留原安装并报告，不安装未经验证的二进制。
4. **安装可回滚的本地修复版**
   - 测试通过后备份并替换当前 npm 全局安装中的 CLI 及配套 helper。
   - 当前 CLI 入口是 hardlink，使用文件替换而不是原地写入，避免只更新了一部分。
   - 记录这是基于 1.0.2 的本地补丁，不冒充官方新版本，并提供恢复原版的方法。
5. **不抢焦点的现场验收**
   - 仅观察当前 Chrome 窗口及菜单，对新获取的元素引用执行只读属性查询，验证别名错误不再出现。
   - 精确绑定窗口 ID、PID 和进程实例，不自动选第一个窗口。
   - 不激活、不重启 Chrome，不导航网页，不退出小红书账号，不读取其他标签页内容，不使用剪贴板或发送键鼠。
   - 窗口不可访问或存在歧义时停止，不切换到 `--headed` 作为退路。

## 范围与限制
- 本次根治已确认的应用名称校验错误；`list-windows` 偶尔为空和 AX 可访问性波动需要验收后再判断，不能预先承诺都由这一补丁解决。
- 不安装 Chrome 扩展、不修改系统权限或插件配置。真正独立的后台网页操作需要受支持的 BrowserSkill 连接，属于后续配置，不混入本次包修复。
- 若未来 npm 升级覆盖本地补丁，需要使用包含官方修复的版本或重新应用补丁。
