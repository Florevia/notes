# 执行 Shell 脚本的方式

执行 Shell 脚本的方式有哪些？（面试高频）
区别在于权限和是否开启子进程。

## 方式 1：source test.sh (或 . test.sh)

- 原理：在当前 Shell 中读取并执行。
- 特点：
  - 不开子进程。
  - 脚本里改变的变量（export）会保留在当前终端里。
  - 通常用于加载配置文件（如 source ~/.zshrc）。

## 方式 2：bash test.sh (或 sh test.sh / zsh test.sh)

- 原理：启动一个新的 Shell 程序（子进程）来解析脚本。
- 特点：
  - 开启子进程。
  - 不需要脚本有“执行权限”（不需要 `chmod +x`）。
  - 跑完后，脚本里的变量修改不会影响当前窗口。

## 方式 3：./test.sh (绝对/相对路径执行)

- 原理：依靠系统内核根据脚本第一行 (Shebang, 如 #!/bin/bash) 决定用什么解释器来跑。

- 特点：
  - 开启子进程。
  - 必须有执行权限！你需要先运行 `chmod +x test.sh`，否则报错 Permission denied。
  - 这是最标准的执行脚本方式。

## 方式 4：exec ./test.sh (极少用，除非想自杀)

- 原理：用新的进程替换当前的 Shell 进程。
- 特点：
  - 脚本跑完后，终端窗口会直接关闭（因为它把自己替换掉了，跑完就没了）。

## 一览图

| 命令        | 是否开子进程 | 是否需要 x 权限 | 变量是否影响当前窗口 | 常用场景                  |
| ----------- | ------------ | --------------- | -------------------- | ------------------------- |
| source file | ❌ 否        | ❌ 不需要       | ✅ 影响              | 加载配置、刷新环境变量    |
| bash file   | ✅ 是        | ❌ 不需要       | ❌ 不影响            | 临时跑脚本、调试          |
| ./file      | ✅ 是        | ✅ 必须         | ❌ 不影响            | 标准运行可执行程序/脚本   |
| exec file   | 替换进程     | ✅ 必须         | -                    | 进程切换、Docker 入口脚本 |
