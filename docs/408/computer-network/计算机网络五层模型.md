# 计算机网络模型

## 五层模型

- 应用层：负责应用程序之间的业务交互逻辑与数据格式标准
- 传输层（运输层）：负责端到端的进程通信。
- 网络层：负责路径选择（路由）与 IP 逻辑寻址
- 数据链路层：负责同一链路上相邻节点（设备）间的帧传输；以太网使用 MAC 地址寻址
- 物理层：物理传输介质上原始比特流（0 和 1）的传输与信号转换

### 数据封装与解封装

以 **HTTP → TCP → IP → 以太网** 为例，每往下一层，都会加入该层需要的控制信息：

```text
应用层        [ HTTP 报文 ]
                    ↓ 加入 TCP 首部
传输层        [ TCP 首部 | HTTP 报文 ]
                    ↓ 加入 IP 首部
网络层        [ IP 首部 | TCP 首部 | HTTP 报文 ]
                    ↓ 加入以太网首部、尾部
数据链路层    [ 帧首部 | IP 首部 | TCP 首部 | HTTP 报文 | 帧尾部 ]
                    ↓ 转换为信号传输
物理层        01011010…… → 电信号 / 光信号 / 无线信号
```

### 各层的主要功能

- 应用层主要面向**互联网的应用场景**，比如网页、邮件、文件中心等。代表协议有 HTTP、SMTP、FTP、POP3、DNS 等。

- 传输层主要面向**端到端的进程通信**，比如 TCP 提供面向连接的可靠传输，UDP 则是无连接的数据报协议，不保证可靠交付；UDP 并不等同于广播。

- 网络层解决**如何定位目标以及如何选择转发路径的问题**，比如 IP 协议。

- 数据链路层解决**同一链路上相邻节点之间的帧传输问题**，以太网的 MAC 地址、二层交换机都属于该层。

- 物理层解决比特流在介质上的信号传输问题，比如通过网线、光纤或无线电传输。

**核心关系：上层的整个数据单元，会成为下层的载荷。**

### 各层最容易混淆的区别

| 层次       | 主要解决的问题                   | 关键标识                 | 典型设备或组件             |
| ---------- | -------------------------------- | ------------------------ | -------------------------- |
| 应用层     | 使用什么网络服务、如何理解消息？ | 域名、URL 等，依协议而定 | 浏览器、Web 服务程序       |
| 传输层     | 数据交给哪个应用进程？           | **端口号**               | 操作系统 TCP/UDP 协议栈    |
| 网络层     | 如何到达目的主机、选择哪条路径？ | **IP 地址**              | 路由器                     |
| 数据链路层 | 在当前链路上交给哪个相邻节点？   | **MAC 地址**（以太网中） | 二层交换机、网卡           |
| 物理层     | 如何把 0 和 1 送过去？           | 不负责 IP/MAC 寻址       | 中继器、集线器、物理收发器 |

> **端口找进程，IP 找主机，MAC 找当前链路上的下一跳。**
>
> 跨路由器转发时，链路层帧会重新封装，源/目的 MAC 通常改变；源/目的 IP 通常不变，NAT 等情况除外。

设备可能同时涉及多个层次，例如网卡通常实现数据链路层和物理层功能，表中列出的是典型对应关系。

## OSI 七层模型

- 应用层
- 表示层
- 会话层
- 传输层
- 网络层
- 数据链路层
- 物理层

### 应用层、表示层与会话层的区别

**应用层管“要做什么”，表示层管“数据怎么表达”，会话层管“对话怎么组织和维持”。**

这三层是 OSI 七层模型中的职责划分；在 TCP/IP 模型中，这些职责通常合并到应用层，并不一定由三个独立模块实现。

#### 应用层：提供什么网络服务？

应用层规定应用程序之间的**业务消息及交互规则**。

- **HTTP**：如何请求网页、如何返回响应。
- **DNS**：如何查询域名对应的 IP 地址。
- **SMTP**：如何发送邮件。

以访问网页为例，应用层关心：“我要请求 `/index.html`，服务器返回成功还是失败？返回什么内容？”

**应用层不等于浏览器界面。** 浏览器是应用程序，HTTP 才是它使用的应用层协议。

#### 表示层：双方如何理解同一份数据？

表示层处理**数据的表示方式与转换**，让发送方和接收方能够正确理解数据。

典型职责包括：

- **编码与格式转换**：字符编码、数据序列化等。
- **压缩与解压缩**：减少传输的数据量。
- **加密与解密**：把明文转换成密文，再恢复。

例如，发送“你好”时，表示层关心：“用 UTF-8 还是其他编码？数据用什么格式表示？是否压缩、是否加密？”

这里说的是**职责归类**：UTF-8、JSON 等不是独立的“表示层协议”；实际互联网中，相关功能可能由应用程序、库或 TLS 等机制实现。

#### 会话层：这场对话如何开始、维持和恢复？

会话层管理双方的**逻辑对话过程**。

典型职责包括：

- 建立、维持和结束会话。
- 协调对话，例如控制哪一方何时发送。
- 设置同步点或检查点，以便中断后恢复。

例如，一次长时间的数据交换中，会话层关心：“我们正在进行哪一次对话？进行到了哪个检查点？中断后能否从检查点继续？”

**会话层不等于 TCP 连接管理。** TCP 属于传输层，负责可靠地传送字节；会话层关注的是建立在通信能力之上的对话组织。网站的登录 session 虽然名称相近，在实际 TCP/IP 系统中通常是应用层机制。

#### 三层对照

| 层次 | 核心问题 | 关键词 |
| --- | --- | --- |
| 应用层 | **交换什么业务消息？** | 网络服务、请求、响应 |
| 表示层 | **消息用什么形式表达？** | 编码、格式、压缩、加密 |
| 会话层 | **这场对话如何组织和维持？** | 会话管理、对话控制、同步恢复 |

**记忆口诀：应用讲业务，表示管格式，会话管对话。**

## TCP/IP 四层模型

- 应用层
- 传输层
- 网际层
- 网络接口层（也称链路层，对应五层模型的数据链路层与物理层）

## 三种分层模型对照

```text
OSI 七层模型          教学五层模型          TCP/IP 四层模型
应用层  ┐
表示层  ├──────────→  应用层  ───────────→  应用层
会话层  ┘
传输层  ───────────→  传输层  ───────────→  传输层
网络层  ───────────→  网络层  ───────────→  网际层
数据链路层 ────────→  数据链路层 ┐
物理层  ───────────→  物理层  ——┴───────→  网络接口层
```

**五层模型是便于学习的划分：保留 TCP/IP 的上层结构，同时把网络接口层拆成数据链路层和物理层。**
