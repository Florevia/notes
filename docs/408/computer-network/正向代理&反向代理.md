# 正向代理 & 反向代理

## 正向代理

### 特点

- 代理对象：客户端 (Client)。
- 场景：VPN、科学上网、公司内网访问外网。
- 原理：客户端想访问 Google，但访问不到。客户端找了一个能访问 Google 的代理服务器，告诉它“帮我拿一下 Google 的首页”。
- 特点：服务器不知道真实的客户端是谁（隐藏了客户端）。

## 反向代理

### 特点

- 代理对象：服务端 (Server)。
- 场景：Nginx 转发请求、负载均衡网关。
- 原理：客户端访问 baidu.com。客户端并不知道百度背后有 10000 台服务器，客户端只连接了百度的入口服务器（反向代理），它帮我派发任务。
- 特点：客户端不知道真实的服务端是谁（隐藏了服务端）。

### 优点

1. 负载均衡

   - 将请求分发到多个后端服务器，提高系统承载能力
   - 按照轮询、权重等算法
   - 避免单点故障，提升可靠性

2. 安全性

   - 隐藏内网架构：黑客只能攻击到反向代理服务器（通常防护很严），无法直接接触到核心的数据库和业务代码服务器。
   - 防火墙作用：可以在这里屏蔽恶意 IP、限制请求频率（防 DDoS）。

3. 解决跨域

   - 浏览器的同源策略限制了前端跨域。但服务器之间是没有同源策略的。
   - 前端请求 -> 反向代理 (同源) -> 后端 API (跨域)。反向代理把后端的数据拿回来，这就绕过了浏览器的限制。

4. SSL 加密卸载

   - HTTPS 加解密非常消耗 CPU。
   - 可以把 SSL 证书配置在反向代理上。
   - 请求到了反向代理解密成 HTTP，再传给内网的业务服务器。
   - 减轻后端服务器的 CPU 负担。

5. 静态资源缓存

   - 静态资源直接由反向代理返回
   - 动态请求转发给后端应用服务器

### 缺点

1. 单点故障风险

   - 如果反向代理服务器宕机，整个服务不可用
   - 需要配置高可用方案（如 Keepalived + 多台 Nginx）

2. 性能瓶颈

   - 所有流量都要经过反向代理，可能成为性能瓶颈
   - 需要足够的硬件资源支持

3. 增加延迟

   - 多了一层转发，增加了请求响应时间
   - 对于低延迟要求的应用需要优化配置
