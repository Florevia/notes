# 核心差异矩阵 (The Big Picture)

我们可以从五个维度来对比：基础设施、构建产物、数据来源、调试能力、容错率。

| 维度           | 本地环境 (Local)                                | 测试环境 (Test/QA/Staging)                                     | 生产环境 (Prod/Online)                                               |
| :------------- | :---------------------------------------------- | :------------------------------------------------------------- | :------------------------------------------------------------------- |
| **核心目标**   | 开发效率 (DX) 快速验证想法，秒级热更新。        | 质量验收 (QA) 模拟真实流程，暴露集成问题。                     | 稳定性与性能 (UX) 极致加载速度，高可用，数据安全。                   |
| **构建模式**   | development 模式 无压缩，保留注释，变量未混淆。 | production 模式 (通常) 可能会开启 Sourcemap 以便 QA 报错定位。 | production 模式 Tree-Shaking，代码压缩 (Minify)，Gzip/Brotli 压缩。  |
| **Source Map** | Inline/Eval 映射精准，构建快，文件体积巨大。    | Hidden/External 有时会上传到 Sentry，浏览器端可能隐藏。        | Hidden/None 绝对不能暴露在公网，防止源码泄露（通常只上传监控平台）。 |
| **网络与 CDN** | localhost 无 CDN，静态资源走本地服务。          | 内网 IP 或受限域名 可能无 CDN，或走独立测试 CDN。              | CDN 全球加速 静态资源推送到 OSS/CDN，强缓存策略 (Cache-Control)。    |
| **数据源**     | Mock 数据 或 Proxy 代理到测试服 API。           | 脏数据 (Dirty Data) 包含大量测试生成的极端边界数据。           | 真实数据 (Real Data) 数据量大，敏感信息加密 (Masking)，写入需谨慎。  |

## 资深视角的深度拆解

### A. 构建产物与性能 (Build Artifacts)

- 本地： 运行的是 `vite dev` 或 `webpack serve`。这里的代码甚至没有被打包到磁盘上，而是存储在 **内存** 中。利用 **HMR** 机制，模块更新时只替换变更部分，**保留应用状态**（如 Pinia/Vuex 中的数据）。

- 线上： 运行的是 `npm run build` 产物。
  - **Tree Shaking**： 移除未引用的死代码。
  - **Scope Hoisting**： 作用域提升，减少函数声明带来的内存开销。
  - **Code Splitting**： 路由懒加载，提取公共 Vendor (React/Vue 核心库) 为单独的 Chunk，利用浏览器缓存。

### B. 数据流与网络安全 (Network & Security)

- 跨域 (CORS)：
  - 本地： 我们常用 `vite.config.ts` 中的 `server.proxy` 来绕过跨域限制。
  - 线上： 必须配置真正的 Nginx 反向代理或由后端配置 `CORS Headers (Access-Control-Allow-Origin)`。这是初级开发最容易踩的坑（本地好好的，上线跨域了）。

- HTTPS：
  - 本地通常是 HTTP。
  - 线上强制 HTTPS。如果你用了 HTTP 的 API 或者某些浏览器 API，在 HTTP 下会失效或报错（Mixed Content 错误）。

### C. 监控与可观测性 (Observability)

- 本地： 出错看 Console 控制台，红屏报错直接显示堆栈。
- 线上： 用户浏览器报错你看不见。我们必须接入 Sentry / LogRocket 等监控平台。

> 关键点： 线上环境需要捕获 `window.onerror` 和 `unhandledrejection`，并结合上传到监控平台的 SourceMap 还原真实报错行数。
