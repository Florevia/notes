骨架屏（Skeleton Screen）在现代前端工程中，早就从单纯的“视觉效果”演变成了一种**架构层面的感知性能优化策略**。

对于一个包含复杂交互和大量数据获取的系统（比如你正在主导的类似“面试王”这样的重度应用），骨架屏的接入不能是零散的，而应该有层级、有策略。

在 Vue 3 + Vite 的技术栈下，骨架屏的使用通常分为三个段位：**组件级封装**、**结合 `<Suspense>` 的异步编排**，以及**构建时的 App Shell 注入**。

---

### 一、 基础段位：纯 CSS 与通用组件封装

骨架屏的本质是一个带有呼吸灯或波浪光影动画的灰色占位块。我们通常会封装一个全局的 `<Skeleton>` 组件。

**1. 核心 CSS 动画实现 (波浪光影)：**
利用 `linear-gradient` 和 `background-position` 可以实现极低开销的扫光动画，完全由 GPU 处理。

```vue
<template>
  <div class="skeleton-block" :style="{ width, height, borderRadius }"></div>
</template>

<script setup lang="ts">
defineProps({
  width: { type: String, default: '100%' },
  height: { type: String, default: '20px' },
  borderRadius: { type: String, default: '4px' }
});
</script>

<style scoped>
.skeleton-block {
  background-color: #f3f3f3;
  /* 核心：使用渐变色和背景大小配合实现光影 */
  background-image: linear-gradient(
    90deg,
    rgba(255, 255, 255, 0) 0,
    rgba(255, 255, 255, 0.4) 20%,
    rgba(255, 255, 255, 0.4) 60%,
    rgba(255, 255, 255, 0)
  );
  background-size: 200% 100%;
  animation: shimmer 1.5s infinite linear;
}

@keyframes shimmer {
  100% {
    background-position: -200% 0;
  }
}
</style>

```

**2. 在业务组件中使用：**
手动维护一个 `isLoading` 状态，使用 `v-if` / `v-else` 切换。这种方式适合局部的、小块的数据加载。

```html
<template>
  <div v-if="isLoading">
    <Skeleton width="60%" height="24px" />
    <Skeleton width="100%" height="16px" style="margin-top: 12px;" />
  </div>
  <div v-else class="real-content">
    </div>
</template>

```

---

### 二、 进阶段位：结合 Vue 3 `<Suspense>` (推荐用法)

在 Vue 3 中，如果你在 `setup` 顶层使用了 `await`（例如等待一个 BFF 接口返回），或者使用了异步组件（`defineAsyncComponent`），手动维护 `isLoading` 状态会变得非常繁琐。

`<Suspense>` 是 Vue 3 专门为异步依赖设计的内置组件，它天然就是为骨架屏而生的。

**用法：** 将异步组件包裹在 `<Suspense>` 中，利用 `#fallback` 插槽自动展示骨架屏。

```vue
<template>
  <Suspense>
    <template #default>
      <QuestionListAsync /> 
    </template>
    
    <template #fallback>
      <div class="question-list-skeleton">
         <Skeleton v-for="i in 5" :key="i" height="80px" style="margin-bottom: 16px;" />
      </div>
    </template>
  </Suspense>
</template>

```

*优势：* 彻底消灭了繁琐的 `const isLoading = ref(true)` 模板样板代码，让视图逻辑与异步获取逻辑完美解耦。

### 三、 架构段位：Vite 构建时注入 App Shell 骨架屏

我们在前面讨论过，如果 Vue 的 JS bundle 很大，首屏依然会白屏。这时候我们需要把“全局骨架屏”直接硬编码到 `index.html` 中。手动写 HTML 很难维护，最好的做法是**通过 Vite 插件在打包时自动注入**。

**1. 准备一段原生的 HTML/CSS 骨架屏：**
新建一个 `skeleton.html`（不需要引入任何外部资源）。

**2. 在 `vite.config.ts` 中编写/配置注入逻辑：**
你可以手写一个极简的 Vite 插件，利用 `transformIndexHtml` 钩子。

```typescript
// vite.config.ts
import { defineConfig } from 'vite';
import vue from '@vitejs/plugin-vue';
import fs from 'fs';
import path from 'path';

// 自定义 Vite 插件：向 index.html 注入骨架屏
function injectAppShellPlugin() {
  return {
    name: 'html-inject-app-shell',
    transformIndexHtml(html: string) {
      // 读取准备好的原生骨架屏代码
      const skeletonHtml = fs.readFileSync(
        path.resolve(__dirname, './src/skeleton.html'), 
        'utf-8'
      );
      // 替换掉 index.html 里的 <div id="app"></div>
      return html.replace(
        '<div id="app"></div>',
        `<div id="app">${skeletonHtml}</div>`
      );
    }
  };
}

export default defineConfig({
  plugins: [vue(), injectAppShellPlugin()]
});

```

*工作流：* 1. 用户访问网站，立刻下载到带有骨架屏的 `index.html`。
2. 浏览器瞬间渲染出骨架屏（耗时可能不到 50ms）。
3. 后台静默下载 Vite 打包出的 `main.js`。
4. Vue 实例挂载到 `#app` 上，接管 DOM，原生骨架屏被真实的 Vue 组件无缝替换。

### ⚠️ 高级工程踩坑提示：骨架屏的“闪烁问题” (FOUC)

当接口返回极快（例如 50ms）时，骨架屏会一闪而过，用户的视觉体验反而会觉得卡顿（也就是常说的 FOUC - 闪烁无样式内容）。

完美的骨架屏方案需要加入**“防闪烁延迟”**策略：如果接口响应时间小于 200ms，干脆不显示骨架屏；如果超过 200ms，才显示骨架屏，并且保证骨架屏至少展示 300ms 再切换到真实内容。
