# Tree Shaking

## 概念

死代码消除技术，最终打包时剔除那些被引入但从未被使用的代码。

## 为什么 Tree Shaking 必须依赖 ESM？

Tree Shaking 的核心前提是静态分析。

- CommonJS 的 `require` 是动态的，打包工具在构建阶段无法确定模块中到底哪些代码被使用了，因此不敢贸然删除代码。

- ESM 的 `import/export` 是静态的、强绑定的。代码在执行前，打包工具（如 Webpack, Rollup）就可以通过扫描代码结构，明确知道哪些导出变量被导入并使用了，哪些完全没有被触碰。

## 核心流程：标记 与 清除

1. 构建 AST（抽象语法树）：

打包工具将源码解析为 AST，分析出整个项目的静态依赖图。

2. 标记作用域与引用轨迹：

工具从入口文件开始，顺藤摸瓜，标记所有被使用过的 import 和 export。

3. 标记死代码：

对于那些在模块中 export 了，但在任何地方都没有被 import 或使用的代码，打包工具会在生成的中间代码中对其打上标记。

4. 压缩工具清除（DCE）：

最后，代码压缩工具（如 Terser 或 UglifyJS）在进行代码混淆和压缩时，会识别这些无用的代码并将其从最终的 Bundle 中彻底物理删除。

### 关键避坑点：副作用 (Side Effects)

有时候打包工具“不敢”摇掉未使用的代码，是因为它无法确定这段代码是否有副作用。

副作用是指：代码除了导出内容外，执行时还修改了全局状态（例如修改了 window 对象，或者重写了 Array.prototype）。

为了让 Tree Shaking 彻底生效，我们通常需要在 `package.json`中配置 `"sideEffects": false`，明确告诉打包工具：“我的项目代码全都是纯模块，没有副作用，请放心大胆地删掉未使用的部分！”（如果是引入全局 CSS 或 Polyfill，则需要配置为数组进行白名单放行，例如 "sideEffects": ["*.css"]）。
