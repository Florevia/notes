# 项目打包后体积优化

## 排查阶段

### 1. 分析打包体积
- webpack 提供了 `webpack-bundle-analyzer` 插件，用于分析打包体积，定位体积较大的模块。vite 提供了分析工具 `rollup-plugin-visualizer`。
- 重点检查：
  - 是否有体积较大的第三方库引入，考虑是否有替代方案。
  - 是否有重复依赖。
  - 分析是否有未使用的代码，通过 Tree Shaking 等技术移除。
  
## 优化阶段

1. 第三方依赖优化
   - 按需引入
```js
  import _ from 'lodash';  // 引入整个 lodash，体积很大！
console.log(_.add(1, 2));


import { add } from 'lodash-es';  // lodash-es 配置了 sideEffects: false
console.log(add(1, 2));
```
   - 使用替代库
2. Tree Shaking
   - 在`package.json`中添加 `"sideEffects": false` 配置，告知 webpack 或 Rollup 哪些模块是“副作用” free 的。
```js
  {
  "sideEffects": [
    "*.css",
    "*.scss",
    "*.less"
  ]
}
```
   - 检查是否有未使用的代码，通过 Tree Shaking 等技术移除。
3. 图片资源优化
   - 压缩图片
   - 用 WebP、SVG 格式替代 jpg/png
4. 代码分割
   - 按需加载组件
   - 提取公共代码，利用缓存机制，减少重复加载。
