### 观察者模式 (Observer) / 发布-订阅模式 (Pub-Sub)

1. 概念： 定义对象间的一种 **一对多的依赖关系**，当一个对象的状态发生改变时，所有依赖于它的对象都得到通知并被自动更新。

2. 区别点（加分项）：
   - 观察者模式： 观察者直接订阅目标（如 Vue 的 Watcher 和 Dep）。

   - 发布-订阅模式： 有一个中间的调度中心（Event Bus）。

3. 前端场景：
   - DOM 事件： document.addEventListener。

   - Vue 响应式原理： Vue 2 的 Object.defineProperty 和 Vue 3 的 Proxy 配合依赖收集。

   - 组件通信： EventBus ($on, $emit)。

#### 手写发布订阅模式

```js
class EventEmitter {
  constructor() {
    // 1. 初始化事件中心
    // 结构：{ 'click': [fn1, fn2], 'change': [fn3] }
    this.events = {};
  }

  // 2. 订阅事件 (on)
  on(eventName, callback) {
    // 如果该事件从未注册过，初始化为空数组
    if (!this.events[eventName]) {
      this.events[eventName] = [];
    }
    // 将回调函数推入数组
    this.events[eventName].push(callback);
  }

  // 3. 发布事件 (emit)
  emit(eventName, ...args) {
    // 获取该事件下的所有回调
    const callbacks = this.events[eventName];

    // 如果有回调，依次执行
    if (callbacks) {
      callbacks.forEach((cb) => cb(...args));
    }
  }

  // 4. 取消订阅 (off)
  off(eventName, callback) {
    const callbacks = this.events[eventName];

    // 如果事件不存在，直接返回
    if (!callbacks) return;

    // 过滤掉需要取消的那个回调函数
    this.events[eventName] = callbacks.filter((cb) => cb !== callback);
  }

  // 5. 只执行一次 (once) - 面试加分点
  once(eventName, callback) {
    // 创建一个包装函数
    const oneTimeWrapper = (...args) => {
      // a. 执行原回调
      callback(...args);
      // b. 立即从订阅列表中移除自己
      this.off(eventName, oneTimeWrapper);
    };

    // 订阅这个包装函数
    this.on(eventName, oneTimeWrapper);
  }
}
```

### 代理模式 (Proxy)

1. 概念： 为其他对象提供一种代理 **以控制对这个对象的访问**。

2. 前端场景：
   - Vue 3 响应式： 使用 ES6 的 Proxy 拦截对象的 get/set 操作，从而实现数据劫持。

   - 网络请求代理： 开发环境配置 webpack-dev-server 的 proxy 解决跨域问题。

   - 缓存代理： 比如对高频计算结果进行缓存，下次直接返回。

### 单例模式 (Singleton)

1. 概念： 保证 **一个类仅有一个实例，并提供一个访问它的全局访问点**。

2. 前端场景：
   - 全局状态管理： Vuex 的 Store（整个应用只有一个 Store）。

   - 全局组件： 全局唯一的 Modal 弹窗、Toast 提示框。

   - Axios 实例： 通常我们会封装一个全局唯一的 Axios 实例用于请求拦截。

### 策略模式 (Strategy)

> 这是告别大量 if-else 或 switch-case 的神器，代码整洁度提升的关键。

1. 概念： 定义一系列的算法，把它们一个个封装起来，并且使它们可相互替换。

2. 前端场景：
   - 表单验证： 不同的验证规则（非空、手机号、邮箱）封装成不同的策略。

   - 权限控制： 不同角色的用户（Admin, User, Guest）渲染不同的组件。

```js
// 糟糕的写法
if (type === 'A') { ... } else if (type === 'B') { ... }

// 策略模式写法
const strategies = {
  'A': () => { /* 逻辑 A */ },
  'B': () => { /* 逻辑 B */ }
}
strategies[type]();
```

### 工厂模式 (Factory)

1. 概念： 定义一个 **创建对象的接口，让子类决定实例化哪一个类**。

2. 前端场景：
   - 通用组件封装： 根据传入的 props (type='primary' | 'danger') 返回不同的 Button 实例。

### 装饰器模式 (Decorator)

1. 概念： **在不改变原对象的基础上，通过对其进行包装拓展（添加属性或方法）**。

2. 前端场景：
   - Axios 拦截器： 在请求发送前或响应接收后进行一些处理。（装饰每个请求）

### 适配器模式 (Adapter)

1. 概念： **将一个类的接口转换成客户希望的另外一个接口。解决接口不兼容问题**。

2. 前端场景：
   - API 数据转换： 后端返回的数据结构（如蛇形命名 user_id）与前端组件需要的数据结构（驼峰命名 userId）不一致时，编写一个适配器函数进行转换。

   - 老旧代码迁移： 封装旧接口，使其符合新框架的调用规范
