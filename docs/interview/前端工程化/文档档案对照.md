# Storybook · Dumi · VitePress · OpenAPI 对照总结

## 一览

| 工具          | 一句话                    | 主要产出                              | 典型使用者               |
| ------------- | ------------------------- | ------------------------------------- | ------------------------ |
| **OpenAPI**   | HTTP API 的标准说明书格式 | `openapi.yaml` / `.json` + Swagger UI | 后端、全栈、前端对接接口 |
| **Storybook** | UI 组件的隔离开发与预览台 | 组件「故事」页                        | 前端组件开发、设计系统   |
| **VitePress** | 基于 Vite 的文档站生成器  | Markdown → 静态文档网站               | 写项目文档、开源官网     |
| **Dumi**      | React 组件库文档工具      | 文档 + 可运行 Demo                    | React 组件库作者         |

## OpenAPI

### 概念

描述 HTTP API 的行业标准（前身常叫 Swagger）。用 YAML/JSON 写清路径、方法、参数、请求体、响应、鉴权等。它本身不是服务，是「接口契约」。

### 用法（简）

1. 手写或由后端框架自动导出 `openapi.yaml` / `openapi.json`（如 FastAPI、NestJS Swagger、SpringDoc）。
2. 用 Swagger UI / Redoc 渲染成可交互文档。
3. 前端用 `openapi-typescript`、`orval`、`swagger-typescript-api` 等生成 TS 类型和请求客户端。

### 作用

- 统一前后端对接口的理解
- 自动出文档，少手写说明
- 生成类型与 SDK，减少联调错误
- 支持 Mock、测试、网关校验

### 使用场景

- 后端提供 REST/HTTP API，需要给前端或第三方对接
- 希望「改接口 → 文档和类型一起更新」
- 微服务、开放平台、BFF 层的接口治理

## Storybook

### 概念

在完整业务应用之外，单独开发和展示 UI 组件的工具。每个组件可有多个「故事」（不同 props / 状态）。

### 用法（简）

```bash
npm create storybook@latest
npm run storybook
```

为组件写 `*.stories.tsx`，用 `args` 描述 Primary、Disabled、Loading 等状态；本地常见地址 `http://localhost:6006`。

### 作用

- 不依赖后端和完整路由就能看组件
- 覆盖边界状态（空数据、超长文案、报错）
- 便于设计 / 测试 / 产品一起评审
- 可接视觉回归、无障碍检查

### 使用场景

- 业务里大量可复用组件
- 设计系统、组件库开发
- 需要快速验证 UI 各种状态

## VitePress

### 概念

基于 Vite 的静态站点生成器，把 Markdown 变成带搜索、侧边栏、主题的文档网站（Vue 官方文档同系思路）。

### 用法（简）

```bash
npm add -D vitepress
npx vitepress init
npm run docs:dev    # 开发
npm run docs:build  # 构建静态站
```

在 `docs/` 下写 `.md`，配置侧边栏与导航即可。

### 作用

- 沉淀规范、上手指南、架构说明、更新日志
- 新成员 onboarding、对外开源项目官网
- 部署简单（静态资源 / GitHub Pages 等）

### 使用场景

- 需要「像官网一样」的项目文档
- 不限技术栈的说明性内容（不一定是组件演示）
- 博客式技术文档、RFC、手册

## Dumi

### 概念

Umi 生态下的 React 组件库文档工具。Markdown 里可直接嵌入可运行的 React 示例，文档与 Demo 一体。

### 用法（简）

```bash
npm install -D dumi
npx dumi setup
npx dumi dev
```

在文档 Markdown 中写 JSX/TSX 代码块，页面上直接渲染演示；常配合组件 API 表格。

### 作用

- 一边写说明一边跑真实组件
- 适合组件库「官网式」文档
- 减少单独维护 demo 工程的成本

### 使用场景

- 发布或维护 React 组件库
- 需要文档页内嵌交互示例
- 国内 Ant Design 一类组件库文档风格

## 四者区别（怎么选）

| 维度 | OpenAPI | Storybook | VitePress | Dumi |
|------|---------|-----------|-----------|------|
| 描述对象 | HTTP 接口 | UI 组件状态 | 任意文档内容 | React 组件 + 文档 |
| 核心文件 | YAML/JSON | `*.stories.*` | Markdown | Markdown + Demo |
| 是否偏「可交互试接口」 | 是（Swagger UI） | 否 | 否 | 组件可点，不是 API 试调 |
| 是否偏「生成 TS 客户端」 | 是 | 否 | 否 | 否 |
| 技术栈绑定 | 无（HTTP） | 多框架 | 偏文档站（Vue 生态友好） | 强绑定 React |
| 和写代码的关系 | 契约与联调 | 组件开发试验台 | 知识沉淀 | 组件库文档站 |

**互补关系（常见组合）**
- 后端 OpenAPI → 前端生成类型/请求；组件用 Storybook 开发；对外总文档用 VitePress 或 Dumi。
- 做 React 组件库：组件开发可用 Storybook，对外文档可用 Dumi（功能有重叠，二选一或分工亦可）。
- 纯业务 App：优先 OpenAPI + Storybook；VitePress/Dumi 按「要不要单独文档站」再加。
