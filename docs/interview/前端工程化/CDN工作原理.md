# CDN工作原理

CDN 的核心目标是 通过将内容缓存到距离用户地理位置最近的服务器（边缘节点）上，来降低网络延迟、减少源站服务器负载，并提升整体的访问速度和稳定性。

要理解CDN的工作原理，最核心的是理解 **DNS解析接管** 和 **缓存/回源机制**。

## 核心组件

* **源站:** 实际存放业务数据和原始文件的服务器。
* **边缘节点:** 遍布全球各地、距离终端用户最近的缓存服务器，负责直接响应用户的访问请求。
* **全局负载均衡系统:** CDN的“大脑”，负责根据用户的IP地址、网络环境、各个边缘节点的负载情况，智能调度用户到最合适的节点。

## CDN的完整工作流程

当用户在浏览器中输入一个接入了CDN的网址（例如 `https://cdn.example.com/image.jpg`）时，整个请求流程如下：

1. **发起请求:** 浏览器向本地DNS服务器（Local DNS）发起域名解析请求，查询 `cdn.example.com` 的IP地址。
2. **CNAME 引导:** Local DNS 向权威DNS服务器查询时，发现该域名配置了 **CNAME 记录**（例如指向了 `example.cdnprovider.com`）。权威DNS会将这个CNAME记录返回给Local DNS。
3. **转交 CDN 调度系统:** Local DNS 接着对这个 CNAME 域名进行解析，这个解析请求会被路由到 CDN 厂商的 GSLB（全局负载均衡）调度系统。
4. **智能调度分配:** GSLB 根据以下几个维度进行综合计算：
* 用户的真实IP地址（判断地理位置和运营商，如北京联通）。
* 各个边缘节点的健康状态、当前负载（CPU、带宽等）。
* 节点到用户的网络延迟。
综合评估后，GSLB 会挑选出一个最优的边缘节点，并将该节点的 IP 地址返回给 Local DNS，最终返回给用户的浏览器。


5. **访问边缘节点:** 浏览器拿到最优节点的 IP 地址后，直接向该边缘节点发起 HTTP/HTTPS 数据请求。

---

### 缓存命中与回源 (Cache Hit & Origin Pull)

边缘节点收到用户的请求后，会根据本地的缓存状态采取不同的行动：

* **缓存命中 (Cache Hit):** 如果边缘节点上已经缓存了请求的文件，并且该缓存未过期（在设定的 TTL 时间内），节点会直接将文件返回给用户。此时请求结束，速度极快。
* **缓存未命中/回源 (Cache Miss / Origin Pull):** 如果边缘节点上没有该文件，或者文件已经过期，节点会向**源站**发起请求（这个过程称为“回源”）。节点从源站获取到最新文件后，会先将其缓存在本地，然后再返回给用户，以便后续其他用户的请求可以直接命中。

### 为什么需要 CDN？

* **突破物理距离的限制:** 光速是有限的，跨国或跨运营商的数据传输必然产生延迟。CDN让数据“睡”在用户家门口。
* **吸收流量峰值:** 面对突发的巨大流量（如秒杀、热点事件），CDN的海量边缘节点可以分担90%以上的流量，防止源站崩溃。
* **安全防护:** 很多CDN集成了DDoS防护和WAF（Web应用防火墙），可以将恶意攻击拦截在边缘节点，保护源站安全。
