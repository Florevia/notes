## Vite 为什么快？

Vite 之所以快，核心在于它利用了 **浏览器原生的 ESM 能力** ，并采用了 **No-Bundle（不打包）** 的开发模式，将繁重的构建工作交给了 **浏览器和高性能工具（esbuild）**。
具体原理可以分为以下三个维度来阐述：

1. **开发环境：基于原生 ESM 的按需编译（核心原理）**
   - 传统的构建工具（如 Webpack）在启动开发服务器前，必须先解析整个依赖图，将所有模块打包成 Bundle，然后才能启动服务。项目越大，启动越慢。

   - Vite 采取了不同的策略：
     - 利用浏览器原生能力：现代浏览器支持 `<script type="module">`。Vite 直接向浏览器提供源码。

     - 按需编译：当浏览器解析到 import 请求时，Vite 开发服务器拦截该请求，仅对该模块进行必要的编译（如 TS 转 JS、Sass 转 CSS）并返回。

   - 结果：启动时间与项目复杂度解耦，几乎是秒开。

2. **依赖预构建：利用 esbuild 的高性能**
   - Vite 将代码分为“源码”和“依赖”两部分。

   - 源码：是我们写的业务代码，变动频繁，通过原生 ESM 加载。

   - 依赖：是 **node_modules** 中的库，变动极少。Vite 使用 esbuild 对其进行预构建。
     - 速度快：esbuild 使用 Go 编写，比基于 Node.js 的打包工具（如 Webpack/Rollup）快 10-100 倍。

     - 格式统一：将 CommonJS/UMD 转换为 ESM。

     - 性能优化：将许多内部模块（如 lodash-es）合并成一个文件，避免浏览器发起成百上千个 HTTP 请求（解决 HTTP 瀑布流问题）。

3. **热更新（HMR）：O(1) 复杂度**
   - Webpack HMR：修改文件后，通常需要重新构建模块及其依赖图的一部分，随着应用规模增长，热更新速度会下降。

   - Vite HMR：利用 ESM，当某个模块修改时，Vite 只需要让浏览器重新请求该特定模块即可。无论项目多大，热更新速度始终保持在一个极低的常量时间（O(1)）。

4. **强缓存策略**
   - 依赖模块：设置了 **强缓存（Cache-Control: max-age=31536000, immutable）**，一旦预构建完成，除非锁文件变动，否则直接走浏览器缓存。

   - 源码模块：使用 **304 协商缓存**，进一步减少网络开销。

## Vite 和 Webpack 有什么不同？

1. 构建原理（核心区别）
   - Webpack (Bundle Base)：是基于 打包（Bundle） 的。在开发服务器启动前，它必须从入口文件开始，递归分析整个依赖图，解析所有模块，打包成 Bundle，然后才启动服务。因此，项目越大，启动越慢。
   - Vite (Native ESM)：是基于 浏览器原生 ESM 的。它利用浏览器去解析 `imports`，开发服务器只负责 **拦截请求并进行按需编译**。启动速度与项目复杂度解耦，几乎秒开。

2. 热更新 (HMR) 机制
   - Webpack：修改文件后，Webpack 需要重新编译 **模块及其依赖，生成新的 Bundle hash**，浏览器通过 **轮询或 WebSocket 获取更新**。随着应用体积增加，HMR 延迟会变大。
   - Vite：修改文件后，Vite 仅需让浏览器重新请求该特定模块（文件）即可。HMR 性能是 O(1) 级别的，无论项目多大，热更新都极其迅速。

3. 底层工具与编译语言
   - Webpack：完全使用 `JavaScript` 编写，运行在 Node.js 上，计算密集型任务（如 AST 解析、代码压缩）受限于 JS 性能，速度较慢。
   - Vite：
     - 开发环境：使用 esbuild（Go 语言编写）进行依赖预构建和文件编译，速度比 JS 快 10-100 倍。
     - 生产环境：使用 Rollup 进行打包。虽然 esbuild 很快，但在代码分割（Code Splitting）和 CSS 处理等细节上，Rollup 目前（截至 2025 年）生成的产物更优，生态插件更成熟。

4. 生态与配置复杂度
   - Webpack：生态极度丰富，也就是“万物皆模块”。但配置繁琐（Loaders/Plugins），对 TypeScript、CSS 预处理器等通常需要手动配置 Loader。
   - Vite：开箱即用。默认支持 TypeScript、JSX、CSS Modules 等，配置简洁。Vite 的插件机制兼容 Rollup 插件，生态扩展性也很好。

## 哪个更好？

“没有绝对的更好，只有更适合。这取决于项目的场景。”

- 首选 Vite 的场景（90% 的现代新项目）：
  - 如果是 Vue3/React 的新项目，或者单页应用 (SPA)。
  - 追求极致的开发体验（秒开、秒热更）。
  - 团队不需要通过复杂的 Loader 做极其魔改的构建逻辑。
  - 理由：开发效率提升极其明显，配置简单，维护成本低。

- 不得不选 Webpack 的场景：
  - 老旧项目迁移：很多老项目依赖了特定的 Webpack Loader 或 Plugin，迁移成本太高。
  - 对兼容性要求极高：如果需要支持 IE11 或更低版本的浏览器（虽然 Vite 也有插件支持 legacy，但 Webpack 在这方面更成熟）。
  - Module Federation (微前端)：虽然 Vite 也有类似插件，但 Webpack 5 原生的 Module Federation 生态更完善。
  - 超大型复杂构建：需要深度定制构建流程，Webpack 的灵活性目前仍是天花板。

## 总结（面试官想听到的一句话）：

“Vite 赢在开发体验和轻量化，利用了现代浏览器的能力，是未来的趋势；而 Webpack 赢在生态成熟度和构建的深度定制能力，适合复杂的存量项目。目前的最佳实践通常是：开发环境用 Vite 享受速度，生产环境用 Rollup（Vite 内置）保证代码质量。”
