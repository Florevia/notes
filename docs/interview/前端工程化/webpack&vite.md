# Vite 和 Webpack 有什么不同？

## 理解 Vite 和 Webpack 的核心差异，其实就是理解“浏览器原生能力”与“Node.js 编译计算”之间的较量。

### 一、 核心原理：Webpack 的“全量打包” vs Vite 的“按需原生 ESM”

#### 1. Webpack：传统的 Bundle（打包）模式

- **工作流**：Webpack 启动开发服务器时，会从入口文件（如 `main.js`）开始，递归解析所有依赖（分析 `import`/`require`），通过各种 Loader 处理文件（Vue, Scss, TS），最终**把所有代码打包成一个或多个巨大的 Bundle 文件**，然后才把这个打包后的结果交给浏览器运行。

- **痛点**：随着项目越来越大，依赖越来越多，越来越慢。

#### 2. Vite：基于原生 ESM 的 Bundleless（无包）模式

- **工作流**：Vite 在开发环境下完全抛弃了打包的概念。它利用了现代浏览器原生支持 ES Modules（`<script type="module">`）的特性。

- **按需供给**：当浏览器解析到 `import App from './App.vue'` 时，会向 Vite 的开发服务器发起一个 HTTP 请求。Vite 服务器拦截到请求后，按需编译这个 `App.vue`，然后立马丢回给浏览器。

- **预构建 (Pre-bundling)**：你可能会问，那 `node_modules` 里的第三方库怎么办？Vite 使用了由 Go 语言编写的 **esbuild** 进行预构建。它把成百上千个小文件（比如 lodash-es）打包成一个单独的模块，并且将 CommonJS 统统转化为 ESM 格式，速度比基于 Node.js 的 Webpack 快 10-100 倍。

---

### 二、 开发体验：冷启动与热更新 (HMR) 速度

正是因为底层机制不同，两者在开发阶段的性能表现有天壤之别。

#### 1. 冷启动速度

- **Webpack**：**慢且随项目变大而变慢**。必须等所有代码和依赖都打包完毕，Dev Server 才能启动并让浏览器访问。

- **Vite**：**毫秒级秒级启动**。Vite 启动时只做两件事：启动一个本地服务器，以及用 esbuild 极速处理一下第三方依赖。你的业务代码根本还没开始编译，服务器就已经 ready 了。

#### 2. 热更新 (HMR) 速度

- **Webpack**：当你修改了一个文件，Webpack 需要重新编译这个模块，并且**重新构建和组装包含该模块的整个 Bundle 片段**。

- **Vite**：**真正的 O(1) 复杂度更新**。当你修改了一个文件，Vite 只需要让浏览器重新请求这一个文件即可。不管你的项目有 10 个组件还是 10000 个组件，热更新速度几乎永远是恒定的极速。

### 三、 生产构建 (Production Build) 的区别

经常有人误解：“既然 Vite 开发时不打包，那生产环境是不是也不打包直接上？”
**答案是：不行，生产环境必须打包。**

为什么？因为如果生产环境也用原生 ESM 挨个请求文件，如果你的应用嵌套了深层的模块，会导致浏览器发起成百上千次网络请求（网络瀑布），这在现阶段的 HTTP 协议下对性能是毁灭性的。

#### 1. Webpack 的生产构建

依然使用 Webpack 自己进行深度打包、Tree-shaking、代码分割和压缩。开发环境和生产环境使用的是**同一套引擎**，这意味着你在开发时看到的效果，高度一致于生产环境。

#### 2. Vite 的生产构建

Vite 在生产环境下，底层的打包引擎切换成了 **Rollup**。

- **为什么不用 esbuild？** 尽管 esbuild 极快，但它在代码分割（Code Splitting）和 CSS 处理等高级生产打包特性上，暂时不如 Rollup 成熟。
- **潜在风险**：Vite 开发态用的是原生 ESM + esbuild，生产态用的是 Rollup。这种**开发与生产环境不一致**，偶尔会导致一些只在生产环境下才暴露出来的幽灵 Bug（虽然随着 Vite 的成熟，这种情况越来越少了）。

### 四、 生态与配置复杂度

- Webpack：生态极度丰富，也就是“万物皆模块”。但配置繁琐（Loaders/Plugins），对 TypeScript、CSS 预处理器等通常需要手动配置 Loader。

- Vite：开箱即用。默认支持 TypeScript、JSX、CSS Modules 等，配置简洁。Vite 的插件机制兼容 Rollup 插件，生态扩展性也很好。

### 五、 核心总结对比表

| 对比维度           | Webpack                                | Vite                                      |
| ------------------ | -------------------------------------- | ----------------------------------------- |
| **底层架构理念**   | Bundle (全量打包机制)                  | Bundleless (基于原生 ESM 且按需编译)      |
| **冷启动速度**     | 慢 (需等待全量打包完成)                | **极快** (服务器即刻启动)                 |
| **热更新 (HMR)**   | 较慢 (随项目体积增大而变慢)            | **极快** (修改谁就替换谁，与项目大小无关) |
| **第三方依赖处理** | Node.js 编译打包                       | **esbuild** (Go 语言编写，性能碾压)       |
| **生产构建引擎**   | Webpack 本身                           | **Rollup**                                |
| **生态与成熟度**   | 极其庞大，插件无所不能，适合巨石老项目 | 生态迅速繁荣，Vue3/React 新项目首选       |
