# 静态 server & 动态 server

## 静态 server

- 职责：搬运工。只负责查找并返回存储在磁盘上的文件（HTML，CSS，JS，图片等），不进行任何逻辑处理或代码执行。
- 代表：Apache、Nginx、Caddy。
- 优势：高并发、低延迟、资源消耗极低，非常适合利用缓存策略。
- 典型场景：
  1. 企业官网/宣传页：内容固定，不需要经常改。
  2. 个人博客/技术文档：比如你现在写的这个 VitePress 笔记。
  3. 静态资源托管 (CDN)：存放图片、视频、JS/CSS 库。

## 动态 server

- 职责：厨师。接受请求后，运行业务代码，查询数据库，处理逻辑，最后拼接出数据或 HTML 返回给客户端。
- 代表：Node.js、Python、Go。
- 消耗：CPU、I/O、内存。
- 优势：
  1. 灵活性：内容是“活”的。比如淘宝首页，商品价格改了数据库，页面自动就变了，不需要改代码。
  2. 个性化：千人千面。比如“我的订单”页面，每个人看到的都不一样。
  3. 交互性：能处理复杂逻辑。比如登录注册、支付、复杂的计算。
- 典型场景：
  1. 电商系统：淘宝、亚马逊（库存实时扣减、价格变动、千人千面推荐）。
  2. 社交媒体：微信、微博（实时消息、动态 Feeds 流）。
  3. 管理后台：企业 ERP、OA 系统（复杂的增删改查、权限控制）。

## 实际使用

（静态 + 动态）

最经典的架构就是：Nginx (静态 Server) + Node.js/Java/Go (动态 Server)。

1. 各司其职：

   - 静态 Server (Nginx) 处理并发能力极强，专门用来抗流量、挡静态请求；

   - 动态 Server (Node.js) 比较脆弱（单线程计算密集），专门用来跑核心逻辑。

2. 安全：

   - 外界只知道 Nginx 的 IP，根本不知道后面真实的 Node.js 服务器在哪里，相当于加了一层防弹玻璃。

3. 负载均衡：

   - Nginx 站在最前面抗压，可以配置 HTTPS 证书、限制 IP 访问、或者把请求分发给后面 10 台 Node.js 服务器。
