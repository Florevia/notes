# 移动端适配方案

## vw/vh

目前新项目（尤其是 ToC 营销页、H5）的首选方案。

- 核心原理：
  - 直接使用 CSS 原生单位 vw。1vw 等于视口宽度的 1%。
  - 最佳实践 (PostCSS 自动化)：
    - 我们在开发时依然按照设计稿（通常是 750px 或 375px）写固定的 px，通过构建工具插件 `postcss-px-to-viewport` 在编译阶段自动将 px 转化为 vw。
  - 优势：
    - 0 Runtime：不需要引入任何 JS 库，完全靠 CSS 渲染，性能最好。
    - 所见即所得：开发体验与写固定像素一致，转换由工具完成。

## rem

过去 5-8 年最流行的方案，虽然地位正在被 vw 取代，但依然存在于大量存量项目中。

- 核心原理：
  - rem 是相对于 HTML 根元素 `font-size` 的单位。
  - 通过 JS 监听屏幕宽度变化，动态修改根元素的 font-size。

  - 现代 REM 写法：
    - 通常配合 `postcss-pxtorem` 插件，将 px 转为 rem。
    - 适用场景：如果项目需要兼容极低版本的浏览器（不支持 vw 的古董机），或者需要通过调整一个根字体大小来实现“整体缩放/字体大小调整”功能时。

## 响应式布局 (Media Queries + Flex/Grid)

这通常用于B端管理系统或官网（需同时兼容 PC、平板、手机）。

- 核心原理：
  - `media`：设置断点，针对不同宽度的设备应用不同的 CSS 规则（如 PC 端三列布局，手机端单列布局）。
  - Flex / Grid：利用弹性盒子的 flex: 1 或 justify-content 能力，解决局部元素的自适应填充问题。
  - 特点：它不是“等比缩放”，而是“布局重排”。
