# 瀑布流的实现方法

## js + 绝对定位 实现

1.  核心逻辑是：维护一个记录每一列当前高度的数组，将下一张图片放在高度最小的那一列。

2.  思路：
    1. 父容器设置 `position: relative`，子项设置 `position: absolute`。
    2. 计算容器能容纳几列（列数 = 容器宽度 / 单项宽度）。
    3. 初始化一个数组 `colHeights`，记录每一列的当前高度（初始都为 0）。
    4. 遍历每个子项：
       - 找到 `colHeights` 中高度最小的那一列（索引为 `minIndex`）。
       - 计算该子项的 `left`（列索引 × 项宽）和 `top`（最小列的高度）。
       - 更新该列高度：`colHeights[minIndex] += 该项高度 + 间隙`。
    5. 所有子项定位完成后，将父容器高度设为 `Math.max(...colHeights)`。

3.  代码

```js
function renderWaterfall() {
  const container = document.getElementById("waterfall-container");
  const items = Array.from(container.getElementsByClassName("item"));

  const gap = 15; // 定义间隙（水平和垂直相同）
  const itemWidth = items[0].offsetWidth;
  const containerWidth = container.offsetWidth;

  // 1. 计算列数：容器宽度 / (项宽 + 间隙)
  // 注意：最后一列右侧不需要间隙，所以先加一个 gap 再除
  const columns = Math.floor((containerWidth + gap) / (itemWidth + gap));

  // 2. 初始化高度数组
  const colHeights = new Array(columns).fill(0);

  items.forEach((item) => {
    // 3. 寻找当前最短的列
    const minHeight = Math.min(...colHeights);
    const minIndex = colHeights.indexOf(minHeight);

    // 4. 计算坐标
    // Left = 索引 * (宽度 + 间隙)
    const leftPosition = minIndex * (itemWidth + gap);
    // Top = 当前列的最短高度
    const topPosition = minHeight;

    item.style.left = `${leftPosition}px`;
    item.style.top = `${topPosition}px`;

    // 5. 更新该列高度：原高度 + 元素高度 + 垂直间隙
    colHeights[minIndex] += item.offsetHeight + gap;
  });

  // 6. 撑开父容器高度，否则父盒子高度为 0
  container.style.height = `${Math.max(...colHeights)}px`;
}

// 核心：确保图片加载后再计算，否则 offsetHeight 为 0
window.addEventListener("load", renderWaterfall);
window.addEventListener("resize", renderWaterfall);
```

## 不定高度 Item 的瀑布流实现

### 1. 核心算法 (贪心算法)

不再是简单的“一行一行”排列，而是维护一个 **列高数组**。

| 步骤            | 说明                                                                                             |
| :-------------- | :----------------------------------------------------------------------------------------------- |
| **1. 初始化**   | 根据屏幕宽度计算列数（如 2 列），初始化高度数组 `[0, 0]`。                                       |
| **2. 遍历元素** | 获取当前元素的高度 `h`。                                                                         |
| **3. 寻找低谷** | 检查高度数组，找到**当前高度最小**的那一列（比如第 0 列高度为 100，第 1 列为 50，则选第 1 列）。 |
| **4. 落子**     | 将元素通过 `absolute` 定位放到该列下方 (`top = minHeight`, `left = colIndex * colWidth`)。       |
| **5. 更新高度** | 该列高度变高了：`cols[1] += h + gap`。                                                           |
| **6. 循环**     | 对下一个元素重复步骤 2-5。                                                                       |

### 2. 关键难点：图片高度未定 (Indeterminate Height)

如果 Item 中包含图片，且没有指定宽高，JS 在计算 `offsetHeight` 时图片可能还没加载完，导致高度计算为 0 或 错误的数值。当图片加载出来后，布局会发生重叠。

**解决方案 A：后端返回每张图片的宽高比例 (推荐)**

- 这是**最稳健**的做法。
- 后端 API 返回数据时带上 `{ width: 800, height: 600 }`。
- 前端根据容器宽度，按比例算出图片渲染后的实际高度：
  ```js
  renderHeight = (containerWidth / imgOriginalWidth) * imgOriginalHeight;
  ```
- 这样图片还没加载，占位盒子的高度就已经定好了，布局绝对正确。

**解决方案 B：前端监听图片加载**

- 必须等图片加载完 (`onload`) 再去触发瀑布流计算。
- 缺点：用户体验差，会有“页面闪烁”或“突然展开”的感觉。
- 优化：使用 `imagesLoaded` 库监听所有图片加载完毕。

```js
// 伪代码逻辑
function layout() {
  const colHeights = [0, 0]; // 假设两列
  const items = document.querySelectorAll(".item");

  items.forEach((item) => {
    // 1. 找到最短列
    const minH = Math.min(...colHeights);
    const minIndex = colHeights.indexOf(minH);

    // 2. 设置位置
    item.style.position = "absolute";
    item.style.top = minH + "px";
    item.style.left = minIndex * itemWidth + "px";

    // 3. 关键：获取实际渲染高度（如果图片没加载完，这里会出错）
    colHeights[minIndex] += item.offsetHeight + gap;
  });
}
```

## 性能优化

### 渲染性能优化

1. 防抖 (Debouncing)
   - 瀑布流通常需要监听 `window.onresize`。如果不做处理，拖动窗口大小时 JS 会每秒执行几十次计算，导致页面卡顿。
   - 优化方案：使用防抖函数，确保在用户停止拖动窗口 200ms 后才触发重排逻辑。

2. 文档碎片 (DocumentFragment)
   - 如果在实现“加载更多”功能，不要每插入一张图片就调用一次 DOM 操作。
   - 优化方案：先将新元素挂载到 `DocumentFragment` 中，最后一次性注入容器，减少浏览器的重绘压力。

### 图片加载优化

瀑布流高度依赖图片尺寸。如果处理不好，会出现图片重叠或页面闪烁。

1. 预设宽高占位 (AspectRatio)
   - 做法：通过计算 (容器宽 / 图片宽) \* 图片高 提前预留空间。
   - 好处：JS 可以立即计算所有坐标，用户看到的是整齐的占位块，加载体验更稳。

2. 懒加载 (Lazy Loading)
   - 不要一次性加载所有图片，尤其是瀑布流这种长列表。
   - 优化方案：使用 `IntersectionObserver` 接口，只有当图片进入（或即将进入）可视区域时，才给 `<img>` 标签的 `src` 赋值。

### 长列表性能优化：虚拟列表 (Virtual List)

当页面有数千个元素时，DOM 节点过多会导致内存溢出和滚动卡顿。

- 核心逻辑：
  - 只渲染当前可视窗口内的几十个 DOM 节点。
  - 对于滚动出视口的元素，将其销毁或回收。
- 使用一个巨大的 padding 或透明容器撑开总高度，模拟滚动条。

适用场景：社交媒体信息流、图片搜索结果页
