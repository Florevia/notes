# 文件上传

## Ajax + FormData

```js
// 拿到input框
const fileInput = document.querySelector("#filePicker");
// 创建一个formdata对象
const formData = new FormData();
// 将文件添加到formdata对象中
formData.append("file", fileInput.files[0]);

// 发送请求
fetch("/upload", {
  method: "POST",
  body: formData,
}).then((res) => console.log("上传成功"));
```

## 大文件上传

### 一、 核心链路拆解

#### 1. 文件切片 (Chunking)

在 JavaScript 中，获取到的 `File` 对象本质上继承自 `Blob`（二进制大对象）。既然是 Blob，它就拥有 `slice` 方法。

#### 2. 计算文件指纹 (Hash) 与 “秒传”

服务器怎么知道你上传的是什么文件？不能靠文件名，因为文件名容易重复。我们必须读取文件内容，计算出一个唯一的 MD5 值（也就是文件指纹）。

- **做法**：引入 `spark-md5` 库来计算。为了防止读取大文件卡死浏览器的渲染主线程，**必须开启一个 Web Worker** 在后台默默计算。

- **秒传逻辑**：在真正上传任何切片之前，先发一个请求给后端：“老板，这个 MD5 值为 `xxx` 的文件你这里有吗？” 如果后端说：“有了，早就存着呢”，前端直接提示“上传成功”（这就是网盘里“秒传”的原理）。

#### 3. 断点续传 (Resumable Upload)

如果秒传失败，说明服务器没有完整的这个文件。那服务器有没有这个文件的一部分呢？

- **做法**：再次询问后端：“老板，MD5 值为 `xxx` 的文件，你目前收到了哪些切片？” 后端返回一个已上传的切片索引数组（比如 `[0, 1, 2, 5]`）。前端拿到后，把这些已经存在的切片从待上传队列里剔除，**只上传缺失的切片**。这就是断点续传的本质。

#### 4. 并发控制 (Concurrency Control)

现在你有 100 个切片需要上传。如果你直接 `Promise.all` 发出 100 个 HTTP 请求，浏览器的并发限制（通常是 6 个）会让请求队列大塞车，甚至导致浏览器卡顿崩溃。

- **做法**：手写一个**异步任务并发控制器**。维护一个“连接池”，保证同时最多只有 3 到 4 个切片在上传。一个传完了，马上把下一个塞进池子里。

```js
async function sendRequest(chunks, limit = 4) {
  const tasks = [...chunks]; // 待上传任务列表
  const results = [];
  const executing = []; // 正在执行的任务

  for (const item of tasks) {
    // 创建上传任务
    const p = uploadChunk(item).then(() => {
      // 执行完后从正在执行的队列中移除
      executing.splice(executing.indexOf(p), 1);
    });
    executing.push(p);

    // 如果达到并发上限，等待其中一个完成
    if (executing.length >= limit) {
      await Promise.race(executing);
    }
  }
  return Promise.all(executing);
}
```

#### 5. 合并请求 (Merge)

当所有的切片都成功发送到后端后，前端主动发送一个 `merge` 请求。

- **做法**：告诉后端：“切片都发完了，你可以按照索引把它们拼接成一个完整的 `.mp4` 文件了。”

### 三、 面试防坑指南

在聊大文件上传时，面试官往往会追问以下几个边缘场景：

1. **“如果切片在传输过程中损坏了怎么办？”**

- _回答_：后端在接收到单个切片后，可以校验该切片的 Hash 值；在最终 Merge 后，再校验一次完整文件的 Hash 值。

2. **“怎么让上传速度更快？”**

- _回答_：除了并发控制，还可以使用 WebRTC 做 P2P 传输（如果业务场景合适），或者借助服务端的 CDN 边缘节点就近上传，甚至利用 WebSocket 保持长连接减少 TCP 握手开销。

3. **“如果文件有 100GB，计算 MD5 要花好几分钟，用户体验太差怎么办？”**

- _回答_：采用**抽样 Hash**。比如只取文件的前 2MB、中间的一小段、最后的一小段，把这三段组合起来算 MD5。虽然牺牲了极小的精确度，但计算速度能提升百倍。

## 代码

```js
let currentTaskId = null;
let currentController = null;
let pollingTimer = null;

async function startJob() {
  currentController = new AbortController();

  try {
    const createRes = await fetch("/api/tasks", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ type: "AI_GENERATE" }),
      signal: currentController.signal,
    });

    const { taskId } = await createRes.json();
    currentTaskId = taskId;

    pollingTimer = setInterval(async () => {
      const statusRes = await fetch(`/api/tasks/${taskId}`);
      const statusData = await statusRes.json();

      console.log("任务状态:", statusData.status);

      if (["SUCCESS", "FAILED", "CANCELLED"].includes(statusData.status)) {
        clearInterval(pollingTimer);
      }
    }, 2000);
  } catch (e) {
    if (e.name === "AbortError") {
      console.log("前端请求已中断");
    } else {
      console.error(e);
    }
  }
}

async function cancelJob() {
  try {
    if (currentController) {
      currentController.abort(); // 先断开当前前端连接
    }

    if (currentTaskId) {
      await fetch(`/api/tasks/${currentTaskId}/cancel`, {
        method: "POST",
      });
    }

    if (pollingTimer) {
      clearInterval(pollingTimer);
    }
  } catch (e) {
    console.error("取消失败", e);
  }
}
```
