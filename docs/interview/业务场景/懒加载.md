# 懒加载

懒加载（Lazy Loading）是一种 **前端性能优化技术**，核心思想是 **“按需加载”**。

即页面初始化时，只加载 **当前视口或逻辑必须的资源**，其他资源等到用户真正需要（如 **点击切换页面、滚动到可视区域**）时再去请求。

它的主要目的是 **减小首屏包体积（Bundle Size），加快首屏渲染速度（FCP），并节省用户带宽**。

在 Vue 项目中，实现懒加载主要覆盖三个场景，底层技术略有不同：

## 路由懒加载（最常用）

这是 **Vue 单页应用（SPA）** 优化的必选项。

- 实现方式：
  在 Vue Router 配置中，不直接引入组件，而是使用箭头函数配合动态导入语法

```js
// router/index.js
const routes = [
  {
    path: "/about",
    name: "About",
    // 只有访问 /about 时才会加载这个组件代码
    component: () => import("../views/About.vue"),
  },
];
```

## 组件懒加载

适用于某些 **体积较大、且不是一上来就展示的组件（比如复杂的弹窗、图表库组件）**。

Vue 3：使用 `defineAsyncComponent` API。

```js
import { defineAsyncComponent } from "vue";
const AsyncChart = defineAsyncComponent(() => import("./HeavyChart.vue"));
```

Vue 2：直接定义组件为一个返回 `Promise` 的函数。

```js
components: {
'my-chart': () => import('./HeavyChart.vue')
}
```

### 组件懒加载的原理和机制

利用构建工具的 **代码分割** 能力，配合 **js 的动态导入** 标准，将代码切割成小块（chunk），仅在需要时 **通过网络请求加载并执行**。

1. 核心基础：ES Module 的 `import()`

- **语法**：`import('./path/to/module')`
- **返回值**：它返回一个 Promise。
- **特性**：Promise resolve 的结果就是那个模块导出（export）的内容。

2. 阶段一：编译时（构建工具的工作）

- **代码分割**

  构建工具在解析代码依赖图时，一旦遇到 `import(...)` 语法，不会将这部分代码打包进主包（bundle.js），而是会把它单独切出来。

- **生成 Chunk**
  它会将这部分组件的代码提取出来，生成一个独立的文件（通常叫 Chunk）。

3. 阶段二：运行时（浏览器的行为）

   当用户在浏览器中访问页面，触发了加载组件的逻辑（比如路由跳转）时，通过以下机制完成加载：

- 当代码执行到 `import('./Foo.vue')` 时，构建工具（如 Webpack）注入的运行时代码（Webpack Runtime）会接管。

  它实际上做了类似这样的事（伪代码）：

  ```js
  // 模拟 Webpack 的 **webpack_require**.e 实现
  function dynamicLoad(chunkUrl) {
    return new Promise((resolve, reject) => {
      // 1. 创建 script 标签
      const script = document.createElement("script");
      script.src = chunkUrl;
      // 2. 监听加载完成
      script.onload = () => {
        // 脚本执行完毕，模块已注册到全局 window.**webpack_modules**
        resolve();
        document.head.removeChild(script); // 扫尾清理
      };
      script.onerror = reject;
      // 3. 插入到 DOM，触发浏览器发起 HTTP 请求
      document.head.appendChild(script);
    });
  }
  ```

## 图片/列表懒加载

当图片滚动到可视区域时才加载 URL。

我的实现：

```js
import { useIntersectionObserver } from "@vueuse/core";

export default {
  // 图片懒加载：在用户进入视口之后，再加载图片
  mounted(el) {
    // 1. 保存图片原本的 src
    const imgSrc = el.src;
    // 2. 把 src 置空
    el.src = "";

    const { stop } = useIntersectionObserver(el, ([{ isIntersecting }]) => {
      if (isIntersecting) {
        // 3. 当图片进入视口时，加载图片
        el.src = imgSrc;
        // 4. 停止监听
        stop();
      }
    });
  },
};
```
### 标准实现
通常封装自定义指令 `v-lazy`，或者使用社区成熟插件（如 vue-lazyload）。

```vue
<img v-lazy="imageSrc" />
```

### 封装 v-lazy 指令

利用浏览器的 `IntersectionObserver` API 来代替传统的 `scroll` 事件监听。

```js
// directives/lazy.js
export default {
  // Vue 3 指令生命周期：mounted (Vue 2 中是 bind/inserted)
  mounted(el, binding) {
    // 1. 预处理，先展示占位图（ Loading状态 ）
    // 实际项目中通常用 dataset 来保存真实的 src， 这里直接用binding.value
    el.src = "/assets/placeholder.png";

    // 2. 定义观察器回调
    const io = new IntersectionObserver(
      (entries) => {
        // entries 是一个数组，因为可以同时监听多个元素，这里我们是一对一
        const entry = entries[0];

        // 3. 核心判断： isIntersecting 代表元素是否可见
        if (entry.isIntersecting) {
          const realSrc = binding.value;

          // 4. 加载真实图片
          // 创建一个image 对象预加载，确保图片下载完再渲染，防止闪烁（可选优化）
          const img = new Image();
          img.src = realSrc;

          img.onload = () => {
            el.src = realSrc;
            // 图片加载成功后的淡入动画逻辑可以在这里加
          };

          img.onerror = () => {
            el.src = "/assets/error.png"; // 加载失败的兜底图
          };

          // 5. 加载完毕后，立刻停止观察该元素，防止内存泄漏
          io.unobserve(el);
        }
      },
      {
        rootMargin: "0px 0px 200px 0px", // 提前 200px 加载，提升用户体验
      }
    );

    // 6. 开始监听
    io.observe(el);
  },
};
```

### intersectionObserver 函数签名

```js
const observer = new IntersectionObserver(callback, options?);
```

1. callback (必填)

当被观察元素的可见性发生变化（即进入或离开视口，或者达到阈值）时触发的函数。

```js
(entries, observer) => void
```

- `entries` (IntersectionObserverEntry[])：这是一个数组。即使你只观察了一个元素，回调返回的也是数组。因为 `IntersectionObserver` 支持使用同一个实例观察多个 DOM 节点。

- 数组中的每一项（entry）包含以下核心只读属性：
  - isIntersecting (Boolean): 最常用。如果为 true，表示目标元素当前是可见的（与根元素相交）。
  - target (Element): 被观察的那个 DOM 节点。
  - intersectionRatio (Number): 相交比例，0.0 到 1.0 之间。
  - boundingClientRect: 目标元素的矩形信息（类似 getBoundingClientRect()）。
  - time: 可见性发生变化的时间戳。
- observer (IntersectionObserver)：
  调用该回调的 Observer 实例本身。通常用于在懒加载完成后调用 observer.unobserve(entry.target) 来停止观察。

2. options (可选)

用于配置观察器的行为，决定了“什么时候触发回调”以及“相对于谁进行计算”。

```ts
{
  root: Element | null,
  rootMargin: string,
  threshold: number | number[]
}
```

- root (默认 null)：
  - 指定根元素（视口）。必须是目标元素的祖先节点。
  - 如果为 null，则默认为浏览器视口 (Viewport)。
- rootMargin (默认 "0px")：
  - 非常关键的属性。它的语法和 CSS 的 margin 一模一样（"top right bottom left"）。
  - 它可以用来扩大或缩小 root 的判定范围。
  - 应用场景：做图片懒加载时，通常设置为 "100px 0px"（底部向下扩大 100px），这样图片在距离视口还有 100px 时就会提前加载，用户滑到时图片已经加载好了，体验更丝滑。
- threshold (默认 0)：
  - 阈值。决定了元素露出多少比例时触发回调。
  - 0：只要元素出现 1px（刚进入）就触发。
  - 1.0：元素完全展示在视口内才触发。
  - 也可以传数组 [0, 0.5, 1]：分别在开始进入、进入一半、完全进入时触发。

### 横向

```js
// 1. 获取横向滚动的父容器
const scrollContainerRef = ref(null);

const initObserver = () => {
  const options = {
    // 关键点1：指定 root 为横向滚动的父容器
    // 如果为 null，则是相对于浏览器视口，这在很多场景下也没问题
    root: scrollContainerRef.value,

    // 关键点2：调整预加载范围
    // 语法：top right bottom left
    // 这里表示：右边还没滑入可视区 200px 时，就开始触发加载
    rootMargin: "0px 200px 0px 0px",

    threshold: 0
  };
```
