# 自定义栈逻辑页面切换效果

在 H5 端完美模拟原生 APP 的跳转体验（即 A -> B -> C，按返回键 C 销毁，B 恢复原来状态，且伴随左右滑动的过渡动画），是前端工程化中一个非常经典且有挑战性的痛点。

原生浏览器的 `history` 是一个黑盒，我们很难准确判断当前是“前进”还是“后退”，且内置的 `<KeepAlive>` 无法自动感知路由的层级关系。

因此，**“虚拟任务栈 + 动态 KeepAlive + CSS Transform”** 是目前最完美的解决方案。

### 一、 核心思路剖析

1. **自定义虚拟任务栈 (Virtual Stack)**：在内存中维护一个数组（类似 Android 的 Task Stack）。路由拦截时，对比目标路由与栈内的数据，判断是 PUSH（入栈/前进）还是 POP（出栈/后退）。
2. **动态 KeepAlive**：基于虚拟栈的判断，动态维护一个 `cachedViews` 数组。前进时加入缓存，后退时将其从缓存数组中剔除，实现“页面销毁”。
3. **动态 Transform 动画**：前进时赋予 `slide-left`（新页面从右侧滑入），后退时赋予 `slide-right`（当前页面向右侧滑出）。

---

### 二、 步骤实现

#### 1. 构建虚拟任务栈与路由拦截器

我们需要在全局状态（例如 Pinia 或独立 JS 文件）中维护栈的状态，并在 `router.beforeEach` 中进行逻辑判断。

```javascript
// store/navigation.js (可以使用 Pinia，这里用单纯的 reactive 演示)
import { reactive, ref } from "vue";

export const virtualStack = reactive(["Home"]); // 虚拟栈，记录路由 name
export const cachedViews = reactive(["Home"]); // KeepAlive 缓存列表，记录组件 name
export const transitionName = ref("slide-left"); // 当前动画方向

// 路由拦截逻辑
export function setupRouterGuard(router) {
  router.beforeEach((to, from, next) => {
    const toName = to.name;
    const fromName = from.name;

    // 寻找目标路由在栈中的位置
    const toIndex = virtualStack.indexOf(toName);

    // 判断逻辑：如果目标路由是栈中的倒数第二个，说明是在执行“后退”操作
    if (toIndex !== -1 && toIndex === virtualStack.length - 2) {
      // === 触发 POP (后退) ===
      transitionName.value = "slide-right"; // 动画：向右滑出

      // 出栈并清除缓存
      virtualStack.pop();
      const cacheIndex = cachedViews.indexOf(fromName);
      if (cacheIndex > -1) {
        cachedViews.splice(cacheIndex, 1); // 从 KeepAlive 中剔除，彻底销毁
      }
    } else {
      // === 触发 PUSH (前进) ===
      transitionName.value = "slide-left"; // 动画：从右侧滑入

      // 入栈并加入缓存
      if (toIndex === -1) {
        virtualStack.push(toName);
      }
      if (!cachedViews.includes(toName)) {
        cachedViews.push(toName);
      }
    }

    next();
  });
}
```

#### 2. 配置 App.vue 视图层

在顶层视图中，将 `Transition` 与 `KeepAlive` 结合，并将我们动态维护的 `cachedViews` 和 `transitionName` 绑定上去。

```vue
<template>
  <div class="app-wrapper">
    <router-view v-slot="{ Component, route }">
      <transition :name="transitionName">
        <keep-alive :include="cachedViews">
          <component :is="Component" :key="route.name" class="page-view" />
        </keep-alive>
      </transition>
    </router-view>
  </div>
</template>

<script setup>
import { cachedViews, transitionName } from "./store/navigation";
</script>
```

#### 3. 利用 Transform 实现 APP 级丝滑动画

要模拟原生 iOS/Android 的效果，不能仅仅是平移，还需要加上**视差效果（Parallax）**和**阴影**。底层页面在被覆盖时，不仅是被遮挡，而是带有轻微的向左偏移和变暗效果。

```css
/* style.css */
.app-wrapper {
  position: relative;
  width: 100vw;
  height: 100vh;
  overflow: hidden; /* 防止滑动时出现横向滚动条 */
}

/* 统一的页面基础样式 */
.page-view {
  position: absolute;
  top: 0;
  left: 0;
  width: 100%;
  height: 100%;
  background-color: #f5f5f5;
  /* 开启 GPU 加速，保证 Transform 丝滑 */
  will-change: transform;
  box-shadow: -2px 0 8px rgba(0, 0, 0, 0.1); /* 给页面左侧加点阴影，立体感更强 */
}

/* ============================== */
/* PUSH: 新页面从右滑入 (slide-left) */
/* ============================== */
.slide-left-enter-active,
.slide-left-leave-active {
  transition: transform 0.35s cubic-bezier(0.25, 0.8, 0.25, 1);
}
/* 新页面从右侧 100% 处进入 */
.slide-left-enter-from {
  transform: translateX(100%);
}
/* 旧页面向左偏移 30% (视差效果) */
.slide-left-leave-to {
  transform: translateX(-30%);
}

/* ============================== */
/* POP: 旧页面向右滑出 (slide-right) */
/* ============================== */
.slide-right-enter-active,
.slide-right-leave-active {
  transition: transform 0.35s cubic-bezier(0.25, 0.8, 0.25, 1);
}
/* 旧页面从左侧 -30% 处恢复 */
.slide-right-enter-from {
  transform: translateX(-30%);
}
/* 当前页面向右侧 100% 处退出 */
.slide-right-leave-to {
  transform: translateX(100%);
}
```

### 三、 ⚠️ 极易踩坑的避坑指南

1. **KeepAlive 的 Name 匹配规则**：
   `<KeepAlive :include="...">` 匹配的是 **Vue 组件内部定义的 `name` 属性**，而**不是** Vue Router 里的路由 `name`。
   **解决：** 必须保证你的路由 `name` 和对应 Vue 组件的 `name` 保持完全一致！(在 Vue 3 `<script setup>` 中，可以使用 `defineOptions({ name: 'YourRouteName' })` 来声明组件名)。
2. **iOS 右滑返回冲突**：
   iOS 设备自带屏幕边缘右滑返回。如果不做处理，浏览器的右滑返回和我们的自定义 Transform 动画会同时触发，导致画面闪烁或崩溃。
   **解决：** 通常 H5 很难完美劫持 iOS 边缘滑动，业内通用解法是将动画的触发时长设置得极短，或者在检测到是 iOS 手势触发的返回时，将 `transitionName` 设为 `''`（无动画），交由 iOS 原生自己渲染滑动。

这套逻辑实现后，你的 H5 就具备了类似原生客户端的骨架。
