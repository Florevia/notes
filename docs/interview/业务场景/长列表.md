# 虚拟列表 + 触底加载（无限滚动）

直接在 `scroll` 事件中用数学公式判断是否触底，会比交叉观察器更精确、且不增加额外开销。

## 核心合并逻辑代码 (`App.vue`)

```vue
<template>
  <div class="virtual-waterfall-demo">
    <h2>虚拟列表 + 触底加载</h2>
    <p>当前总数据量：{{ list.length }} 条</p>
    <!-- 可视区域 -->
    <div class="viewport" ref="viewportRef" @scroll="handleScroll">
      <!-- 占位元素，撑开滚动条 -->
      <div class="phantom" :style="{ height: phantomHeight + 'px' }"></div>
      <!-- 列表区域 -->
      <div class="list-area" :style="{ transform: `translateY(${offsetY}px)` }">
        <div class="list-item" v-for="item in visibleData" :key="item.id">
          {{ item.content }}
        </div>

        <div class="loading-tips">
          <span v-if="isLoading">拼命加载中...</span>
          <span v-else-if="isFinished">我是有底线的</span>
        </div>
      </div>
    </div>
  </div>
</template>

<script setup>
import { ref, computed, onMounted } from "vue";

// --- 核心配置参数 ---
const itemHeight = 60; // 每条数据的固定高度
const containerHeight = 400; // 可视容器的固定高度
const bufferCount = 4; // 上下缓冲渲染的节点数（防白屏）

// --- 状态管理 ---
const list = ref([]); // 总数据源
const scrollTop = ref(0); // 当前滚动的距离
const isLoading = ref(false);
const isFinished = ref(false);

// --- 虚拟列表核心计算 (The Math) ---
// 1. 整个列表的绝对总高度 (用于撑开滚动条)
const phantomHeight = computed(() => list.value.length * itemHeight);

// 2. 当前可视区能装下几个元素？
const visibleCount = Math.ceil(containerHeight / itemHeight);

// 3. 计算可视数据的起始索引 (startIndex)
const startIndex = computed(() => {
  // 向下取整，算出当前滚过了几个完整元素
  let start = Math.floor(scrollTop.value / itemHeight);
  // 减去缓冲个数，防止往回滑时白屏 (不能小于0)
  return Math.max(0, start - bufferCount);
});

// 4. 计算可视数据的结束索引 (endIndex)
const endIndex = computed(() => {
  // 起始索引 + 可视个数 + 缓冲个数
  return Math.min(
    list.value.length,
    startIndex.value + visibleCount + bufferCount * 2
  );
});

// 5. 截取真正需要渲染到 DOM 树里的数据片段
const visibleData = computed(() => {
  return list.value.slice(startIndex.value, endIndex.value);
});

// 6. 计算真实渲染层需要向下偏移的距离
const offsetY = computed(() => {
  // 让渲染层跟着 startIndex 往下走
  return startIndex.value * itemHeight;
});

// --- 滚动与触底加载逻辑 ---
const handleScroll = (e) => {
  const target = e.target;
  // 更新当前的滚动距离，触发上述所有 computed 的重新计算！
  scrollTop.value = target.scrollTop;

  // 【触底加载检测】
  // 核心公式：滚动高度 + 容器视口高度 >= 总内容高度
  // 这里减去 50 是为了留一点提前量，不要等完全滑到底才去加载
  if (target.scrollHeight - target.scrollTop - target.clientHeight < 50) {
    if (!isLoading.value && !isFinished.value) {
      fetchData();
    }
  }
};

// 模拟网络请求获取数据
const fetchData = () => {
  isLoading.value = true;

  setTimeout(() => {
    const currentLen = list.value.length;
    // 每次猛烈加载 10,000 条数据进行压测！
    const newData = Array.from({ length: 10000 }).map((_, i) => ({
      id: currentLen + i + 1,
      content: `我是第 ${currentLen + i + 1} 条海量数据`,
    }));

    list.value.push(...newData);
    isLoading.value = false;

    // 假设限制最大只加载 5 万条
    if (list.value.length >= 50000) {
      isFinished.value = true;
    }
  }, 500); // 模拟 0.5s 网络延迟
};

// 初始化加载第一批数据
onMounted(() => {
  fetchData();
});
</script>

<style scoped>
.virtual-waterfall-demo {
  padding: 20px;
}
/* 1. 可视区必须相对定位，限制高度，允许纵向滚动 */
.viewport {
  position: relative;
  width: 350px;
  height: 400px;
  border: 2px solid #3498db;
  border-radius: 8px;
  overflow-y: auto;
  background-color: #f9f9f9;
}
/* 2. 占位层：只管撑起高度，绝对定位在最左上角 */
.phantom {
  position: absolute;
  left: 0;
  top: 0;
  right: 0;
  z-index: -1;
}
/* 3. 真实渲染层：绝对定位，通过 transform 跟着视口往下走 */
.list-area {
  position: absolute;
  left: 0;
  top: 0;
  right: 0;
}
.list-item {
  height: 60px; /* 必须和 JS 里的 itemHeight 一致 */
  line-height: 60px;
  padding: 0 20px;
  border-bottom: 1px solid #eee;
  box-sizing: border-box;
  background-color: #fff;
  transition: background-color 0.2s;
}
.list-item:hover {
  background-color: #e8f4fd;
}
.loading-tips {
  text-align: center;
  line-height: 60px;
  color: #999;
}
</style>
```

### 💡 核心运转机制拆解：

1. **一瞬间加载 1 万条数据也不卡**：
   你看代码里的 `fetchData`，我故意一次性往数组里 push 了 10,000 条数据。如果直接渲染，浏览器必死无疑。但因为有了 `visibleData` 的截取，无论数组多大，DOM 树里永远只有十几个 `<div class="list-item">`。
2. **纯靠数学驱动的滚动**：
   当你滚动滚轮时，`scrollTop` 增加 -> `startIndex` 变大 -> `visibleData` 截取出新的数据段 -> `offsetY` 将整个内容区往下推。这一切都在一瞬间发生，视觉上就像真实的列表在向上滑一样。
3. **触底加载的完美融合**：
   就在我们监听 `scroll` 事件进行数学计算的同时，顺手做了一个判断：当滚动条快要贴底的时候（`scrollHeight - scrollTop - clientHeight < 50`），直接触发 `fetchData` 去塞入新的 10,000 条数据。随着数据的增加，`phantomHeight` 会自动变高，滚动条变长，滑动得以继续。
