# 瀑布流

## 方案

JavaScript + 绝对定位

## demo

```html
<div id="waterfall-container">
  <div class="item" style="height: 150px;">1</div>
  <div class="item" style="height: 250px;">2</div>
  <div class="item" style="height: 120px;">3</div>
  <div class="item" style="height: 300px;">4</div>
  <div class="item" style="height: 180px;">5</div>
  <div class="item" style="height: 220px;">6</div>
</div>
```

```css
#waterfall-container {
  position: relative;
  width: 100%;
}

.item {
  position: absolute;
  width: 200px; /* 瀑布流的关键：列宽必须固定 */
  background-color: #3498db;
  color: white;
  font-size: 24px;
  display: flex;
  align-items: center;
  justify-content: center;
  transition: all 0.3s ease; /* 让窗口缩放时有平滑移动的动画 */
}
```

```js
function renderWaterfall() {
  const container = document.getElementById("waterfall-container");
  const items = container.getElementsByClassName("item");

  // 1. 定义基础参数
  const itemWidth = 200; // 卡片宽度
  const gap = 15; // 卡片之间的间距

  // 2. 计算当前屏幕能放下几列
  const containerWidth = container.clientWidth;
  const columns = Math.floor(containerWidth / (itemWidth + gap));

  // 3. 初始化一个数组，用于记录每一列的当前总高度
  // 如果是 3 列，数组初始为 [0, 0, 0]
  const columnHeights = new Array(columns).fill(0);

  // 4. 遍历所有卡片，进行位置计算
  for (let i = 0; i < items.length; i++) {
    const item = items[i];

    // 找出目前高度最短的那一列的值，以及它的索引
    const minHeight = Math.min(...columnHeights);
    const minIndex = columnHeights.indexOf(minHeight);

    // 设置当前卡片的 left 和 top
    item.style.left = minIndex * (itemWidth + gap) + "px";
    item.style.top = minHeight + "px";

    // 关键：更新这列的高度 (原高度 + 当前卡片高度 + 间距)
    columnHeights[minIndex] += item.offsetHeight + gap;
  }
}

// 页面加载完毕后执行
window.onload = renderWaterfall;

// 监听窗口大小变化，重新触发布局计算 (实现响应式)
window.onresize = () => {
  // 实际开发中这里通常会加一个防抖 (debounce)
  renderWaterfall();
};
```

### 核心痛点与解决方案

1. 图片高度塌陷与计算错乱（最经典的坑）
   问题描述：瀑布流的核心算法（找最短列插入）强依赖于元素的高度。如果图片是异步加载的，计算位置时图片还没撑开容器，高度为 0。等图片加载完撑开高度后，卡片就会严重重叠或出现巨大的留白。

解决方案：

后端兜底（最优解）：强依赖后端在 API 返回的数据中直接携带图片的 width 和 height。前端在渲染前，按比例计算出卡片高度，直接占位。

前端预加载：如果后端死活不给，前端只能用 new Image() 或 img.onload 把这批图片在内存里静默加载一遍，拿到高度后再执行瀑布流算法（缺点是出图较慢，会有一段白屏时间）。

2. 窗口缩放 (Resize) 导致的疯狂重排 (Reflow)
   问题描述：用户如果拖拽改变浏览器窗口大小，列宽或列数会发生变化，导致所有卡片的位置需要重新计算。由于 resize 事件在一秒内会触发几十次，这会让浏览器的主线程瞬间被密集的 DOM 操作卡死。

解决方案：

必须给 window.addEventListener('resize', ...) 绑定防抖函数（Debounce）。比如设置 200ms 的延迟，只有当用户停止拖拽窗口后，才执行一次统一的位置重排。

3. 路由跳转后的状态丢失
   问题描述：用户在瀑布流刷了 500 条数据，滑到了第 50 页，点击某张卡片进入详情页。看完后点击浏览器的“返回”，结果瀑布流重新挂载，回到了第一页顶部，用户体验瞬间崩溃。

解决方案：

配合现代框架的路由缓存机制（比如 Vue 的 `<KeepAlive>`）。

将加载的数据列表、当前的页码、以及记录到的离开时的 scrollTop 滚动距离存入全局状态管理（如 Pinia/Redux）或 sessionStorage 中。返回时直接恢复数据并无感滚动到历史位置。
