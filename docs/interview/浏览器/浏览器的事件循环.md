# 浏览器的事件循环

在回答时间循环机制的时候，一定要先问清是什么运行时。

## 为什么需要事件循环？

- JavaScript 是一门 **单线程** 语言，这意味着它只有一个 **调用栈**，同一时间只能做一件事。

- 但网页中充满了各种 **耗时操作**（如网络请求、定时器、事件监听）。如果同步等待它们完成，页面就会“卡死”。

- 因此就需要事件循环机制，它协调着 **1.主线程**、**2.Web APIs**、**3.任务队列**，使得 JS 能够实现 **非阻塞的异步并发**。

## 事件循环的三大核心组件

- 调用栈 (Call Stack)：主线程执行代码的地方（先进后出）。

- Web APIs：浏览器提供的后台多线程能力（如 DOM, ajax, setTimeout）。

- 任务队列 (Task Queue)：异步任务完成后，回调函数排队等待进入调用栈的地方（先进先出）。

## 宏任务与微任务

- 宏任务 (Macrotask/Task)：
  - script (整体代码)
  - setTimeout
  - setInterval
  - I/O 操作
  - 特点：按顺序一个一个执行。

- 微任务 (Microtask)：
  - Promise.then/catch/finally
  - MutationObserver
  - queueMicrotask()
  - 特点：优先级极高，会清空执行（如果微任务中又产生了微任务，会一直执行，直到队列为空）。

- 特殊：
  - requestAnimationFrame（在UI渲染之前，微任务清空之后进行）
  - UI 渲染（在当前宏任务执行完和微任务清空后）

## 事件循环的运转流程（Tick）

这是整个机制的核心，一个完整的循环（Tick）严格遵循以下步骤：

1. **执行同步代码**：这其实是 **第一个宏任务**（Script 整体代码）。从宏任务队列取出它，压入调用栈执行。

   > 💡 **误区提示**：很多人以为微任务比宏任务快，所以最先执行。其实“同步代码”本身就是第一个宏任务。只有等它执行完了，才会去清空微任务。

2. 处理微任务队列：同步代码执行完毕，检查微任务队列。如果有微任务，依次出队并执行，直到微任务队列彻底为空。

3. UI 渲染：如果浏览器到了渲染时机（通常是 16.6ms 一次），GUI 线程会接管并渲染页面。

4. 开始下一轮：检查宏任务队列，取出下一个宏任务，回到第 1 步。

一句话口诀："执行一个宏任务 -> 清空所有微任务 -> 渲染页面 -> 开启下一个宏任务"

## 米哈游真题

### 1.

```js
console.log("start");

setTimeout(() => {
  console.log("setTimeout1");
});

Promise.resolve()
  .then(() => {
    console.log("Promise1");
    setTimeout(() => {
      console.log("setTimeout2");
    });
  })
  .then(() => {
    console.log("Promise2");
  });

requestAnimationFrame(() => {
  console.log("rAF1");
});

console.log("end");
```

- 输出结果：

  ```
  start
  end
  Promise1
  Promise2
  rAF1
  setTimeout1
  setTimeout2
  ```

- 思路：

  > 宏任务 -> 微任务 -> [rAF 回调] -> [Layout] -> [Paint]

### 2.

```js
class Parent {
  name = (function () {
    console.log('parent init');
    return 'parent';
  })();

  constructor() {
    console.log('parent constructor');
    this.run();
    this.runA();
  }

  run() {
    console.log('parent run');
  }

  runA() {
    console.log('parent runA');
  }
}

class Child extends Parent {
  name = (function () {
    console.log('child init');
    return 'child';
  })();

  innerName: undefined | number;

  constructor() {
    super();
    console.log('child constructor');
    console.log(this.innerName);
  }

  run() {
    this.innerName = 1;
    console.log('child run');
  }

  runA() {
    console.log('child runA');
  }
}

new Child();

```
