# JS 与 CSS 的阻塞行为详解

这是前端性能优化和面试中极容易混淆的考点。我们需要区分

- **阻塞解析 (Parser Blocking)**
- **阻塞渲染 (Render Blocking)**

## 1. JavaScript 为什么会阻塞解析？

### 原理

当浏览器在构建 DOM 树时，如果遇到 `<script>` 标签，它必须**暂停 DOM 的构建**，将控制权移交给 JavaScript 引擎。

1.  **下载**：如果是外部脚本，需要先下载（网络耗时）。
2.  **执行**：下载完后立即执行 JS 代码。
3.  **恢复**：JS 执行完毕后，浏览器才继续构建 DOM。

### 为什么这么设计？

因为 JavaScript 可能会操作 DOM（例如 `document.write`，或者修改已有的 DOM 节点）。如果浏览器不暂停解析，继续构建 DOM，而随后的 JS 代码又修改了 DOM，那么之前的构建工作就白费了，甚至可能导致竟态状态（Race Condition）。

> **结论**：**JS 默认会阻塞 DOM 的解析（Parsing）和渲染（Rendering）。**

---

## 2. CSS 会阻塞解析吗？

### 结论

- **CSS 不会阻塞 DOM 的解析 (Non-blocking Parsing)**：浏览器在下载和解析 CSS 时，仍然会继续构建 DOM 树。

- **CSS 会阻塞页面的渲染 (Render Blocking)**：浏览器必须等待 CSSOM 构建完成才能开始渲染（Paint）。否则页面会先显示无样式的混乱内容（FOUC），然后突然变样。

- **CSS 会阻塞 JS 的执行**：这是很多人的知识盲区。
  - 如果 JS 脚本在 CSS 之后，浏览器通常会等待 CSSOM 构建完成才执行 JS。

  - **原因**：JS 可能会请求样式信息（如 `getComputedStyle`）。如果 CSS 还没解析完，JS 拿到的数据就是错误的。

## 3. 如何解决 JS 阻塞解析的问题？

核心思路是：

- **异步加载**
- **延迟执行**

### 3.2 `preload` (预加载当前页资源)

```html
<link rel="preload" href="critical.js" as="script" />
<link rel="preload" href="font.woff2" as="font" crossorigin />
```

- **行为**：告诉浏览器**立即开始下载**，但**不执行**。
- **优先级**：高，与当前页面关键资源同等优先。
- **执行时机**：需要手动触发（如后续的 `<script src="critical.js">`）。
- **适用场景**：当前页面的关键资源（首屏字体、关键 JS/CSS）。

### 3.3 `prefetch` (预取下一页资源)

```html
<link rel="prefetch" href="next-page.js" as="script" />
```

- **行为**：告诉浏览器在**空闲时**下载资源，为后续导航做准备。
- **优先级**：低，不影响当前页面加载。
- **执行时机**：需要手动触发。
- **适用场景**：用户**即将访问**的下一个页面的资源。

### 3.4 `defer` 属性 (推荐)

```html
<script src="app.js" defer></script>
```

- **行为**：**异步下载**，但**延迟执行**。
- **执行时机**：HTML 解析完成之后，`DOMContentLoaded` 事件触发之前。
- **顺序**：保证按照在 HTML 中出现的顺序依次执行。
- **适用场景**：依赖 DOM 的脚本，或脚本之间有依赖关系。

### 3.5 `async` 属性

```html
<script src="analytics.js" async></script>
```

- **行为**：**异步下载**，下载完毕后**立即执行**（执行时会阻塞 HTML 解析）。
- **执行时机**：下载完就执行，不确定具体时间。
- **顺序**：**无法保证顺序**（谁先下载完谁先执行）。
- **适用场景**：完全独立的脚本（如埋点分析、广告），不依赖 DOM，也不被其他脚本依赖。

## 4. 总结对比图

| 模式             | HTML 解析 | 脚本下载     | 脚本执行    | 是否阻塞 HTML 解析？ | 执行顺序 |
| :--------------- | :-------- | :----------- | :---------- | :------------------- | :------- |
| `<script>`       | 暂停      | 同步         | 立即        | **是**               | 顺序执行 |
| `<script async>` | 继续      | 异步         | 下载完立即  | **是** (仅执行阶段)  | **乱序** |
| `<script defer>` | 继续      | 异步         | HTML 解析后 | **否**               | 顺序执行 |
| `preload`        | 继续      | 异步（高优） | 需手动触发  | **否**               | —        |
| `prefetch`       | 继续      | 异步（低优） | 需手动触发  | **否**               | —        |
