# SSL/TLS

## 是什么

用于在计算机网络上提供安全通信的加密协议。

- SSL (Secure Sockets Layer)：安全套接字层，由 Netscape 公司设计，是早期的标准（1.0, 2.0, 3.0）。目前因为存在安全漏洞，已被废弃。

- TLS (Transport Layer Security)：传输层安全协议，是 SSL 的继任者和升级版（IETF 标准化）。
  - 目前主流使用的是 TLS 1.2。
  - 最新一代是 TLS 1.3（速度更快，安全性更高）。

## 核心作用

HTTP 是明文传输的，SSL/TLS 在 TCP 和 HTTP 之间加了一层，提供了以下三个保障：

- 机密性 (Confidentiality)：对数据进行加密，防止中间人窃听（防窃听）。

- 完整性 (Integrity)：防止数据在传输过程中被篡改（防篡改）。

- 身份认证 (Authentication)：通过证书机制，证明服务器就是它声称的那个服务器（防冒充）。

## 加密手段 (混合加密)

SSL/TLS 使用了混合加密机制：

- **非对称加密**：用于握手阶段。用于身份认证和安全地交换“会话密钥”。（特点：运算慢，但安全）

- **对称加密**：用于数据传输阶段。使用握手时协商好的“会话密钥”加密实际传输的数据。（特点：运算快）

## HTTPS (TLS 1.2) 握手与加密详细流程

以最经典的 TLS 1.2 基于 RSA 算法的握手为例（虽然现代多用 ECDHE，但 RSA 逻辑最容易理解和讲述）。

整个过程可以概括为：“打招呼 -> 查户口 -> 换钥匙 -> 开始聊天”。

### 第一步：Client Hello (打招呼)

客户端（浏览器）向服务器发起请求：

- 支持的协议版本：比如 TLS 1.2。

- 支持的加密套件列表：比如 RSA, AES 等。

- 随机数 A (Client Random)：关键数据 1，用于后续生成会话密钥。

### 第二步：Server Hello (回应)

服务器收到请求后回复：

- 确认协议版本。

- 选定的加密套件：从客户端给的列表中选一个。

- 服务器证书 (Certificate)：包含服务器公钥、CA 签名等信息。

- 随机数 B (Server Random)：关键数据 2，用于后续生成会话密钥。

### 第三步：客户端验证证书 (查户口)

浏览器收到证书后，进行严格校验（这一步非常关键）：

- 验证机构：检查证书是否由受信任的 CA（根证书颁发机构）签发。

- 完整性：用 CA 的公钥解密签名，对比哈希值，防止证书被篡改。
  有效期：检查是否过期。
  域名匹配：检查证书上的域名和访问的域名是否一致。
  如果验证失败，浏览器会弹出“连接不安全”的红色警告。

### 第四步：密钥交换 (换钥匙)

验证通过后，开始生成最终用来通信的“会话密钥”：

- 客户端生成一个新的随机数，称为 Pre-Master Secret (预主密钥)。

- 客户端使用证书中的服务器公钥，对 Pre-Master Secret 进行加密。

- 客户端将加密后的 Pre-Master Secret 发送给服务器。

- 服务器收到后，使用自己的私钥解密，得到了 Pre-Master Secret。

此时此刻：

- 客户端和服务器都拥有了三个要素：随机数 A、随机数 B、Pre-Master Secret。

- 双方使用相同的算法，将这三个数混合，计算出最终的 Session Key (会话密钥 / Master Secret)。

### 第五步：Finished (测试连接)

- 客户端：发送一个用 Session Key 加密的消息（"Finished"），告诉服务器“我准备好了，以后都用这个密钥聊”。

- 服务器：也发送一个用 Session Key 加密的消息，确认“我也准备好了”。

### 第六步：加密通信 (开始聊天)

握手结束。

此后所有的 HTTP 请求和响应，都使用这个 Session Key 进行对称加密传输。

状态：TLS 握手结束。此时双方都拿到了同样的会话密钥 (Session Key)。
