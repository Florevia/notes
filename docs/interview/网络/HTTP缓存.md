# HTTP 缓存

HTTP 缓存是 Web 性能优化的关键技术。它将服务器返回的 **静态资源（HTML, CSS, JS, 图片等）** 存储在 **本地（memory cache 内存或 disk cache 磁盘）** ，当下次需要请求相同资源时，直接从本地读取，从而 **减少网络请求、降低服务器压力、加快页面加载速度**。

## 缓存分类

浏览器缓存主要分为两大类：**强缓存 (Strong Cache)** 和 **协商缓存 (Negotiated Cache)**。

### 1. 强缓存 (Strong Cache)

**特点**：  
浏览器直接判断本地缓存是否过期。如果未过期，**直接使用本地缓存，不发送 HTTP 请求给服务器**。

**状态码**：  
`200 OK` (from memory cache 或 from disk cache)

**控制字段 (HTTP Header)**：

- **`Cache-Control` (HTTP/1.1 - 推荐)**
  - `max-age=3600`：表示资源在 3600 秒内有效。
  - `no-cache`：不使用强缓存，每次都去服务器验证（走协商缓存，每次要带上 `If-Modified-Since` 或 `If-None-Match`）。
  - `no-store`：禁止任何缓存（包括强缓存和协商缓存），每次都从服务器拉取最新数据。
  - `public`：客户端和代理服务器都可以缓存。
  - `private`：只有客户端可以缓存。
  - `immutable`：表示资源永远不会变（甚至用户刷新也不重新请求，除非强制刷新）。

- **`Expires` (HTTP/1.0 - 老旧)**
  - 值是一个绝对时间 (GMT 格式)，如 `Web, 11 Jan 2026 08:00:00 GMT`。
  - **缺点**：如果客户端时间被修改，或者与服务器时间不一致，会导致判定错误。
  - **优先级**：如果同时存在 `Cache-Control`，则 `Expires` 会被忽略。

---

### 2. 协商缓存 (Negotiated Cache)

**特点**：  
强缓存失效（过期）或被禁用（`no-cache`）时，浏览器会携带缓存标识向服务器发起请求，**由服务器决定是否使用缓存**。

- 如果资源未修改：服务器返回 `304 Not Modified`，浏览器读取本地缓存。
- 如果资源已修改：服务器返回 `200 OK` 和最新的资源内容。

**控制字段 (成对出现)**：

#### A. 基于修改时间 (`Last-Modified`)

1.  **响应**：服务器返回 `Last-Modified: Wed, 11 Jan 2026 08:00:00 GMT`。
2.  **请求**：下次请求时，浏览器带上 `If-Modified-Since: Wed, 11 Jan 2026 08:00:00 GMT`。
3.  **判断**：**服务器对比文件的最后修改时间**。如果一致，返回 304；如果不一致，返回 200 + 新内容。

- **缺点**：
  - 时间精度通常只能到秒级。如果 1 秒内修改多次，无法感知。
  - 有时文件由于某种原因被“碰”了一下（修改时间变了），但内容没变，也会导致缓存失效。

#### B. 基于内容指纹 (`ETag`) - **更精准**

1.  **响应**：服务器计算文件内容的哈希值 (Hash/Fingerprint)，返回 `ETag: "abc-123456"`。
2.  **请求**：下次请求时，浏览器带上 `If-None-Match: "abc-123456"`。
3.  **判断**：服务器重新计算当前文件的 Hash，与 `If-None-Match` 对比。一致则 304，不一致则 200。

- **优点**：非常精准，只要 **内容变了，ETag 必变**。
- **缺点**：计算 Hash 需要消耗服务器 CPU 资源。
- **优先级**：`ETag` > `Last-Modified`。

## 缓存位置

浏览器查找缓存的位置和优先级顺序

1.  **Service Worker Cache**：运行在浏览器后台的独立线程，通过 JS 拦截网络请求。开发者可以自定义缓存逻辑（存什么、怎么存、什么时候失效）
2.  **Memory Cache (内存缓存)**：
    - 读取快，随着进程/Tab 关闭而释放（标签页关闭）。
    - 通常存放较小的资源或当前页面频繁使用的资源（如脚本、图片）。
3.  **Disk Cache (磁盘缓存)**：
    - 读取较慢，但持久存储。
    - 通常存放较大的文件（如 CSS, 大图）。
4.  **Push Cache** (HTTP/2 推送缓存)。

## Cache-Control 指令

**响应指令**:

```http
Cache-Control: max-age=3600
```

- `max-age=<seconds>`: 资源被认为是新鲜的最大时间（秒）
- `s-maxage=<seconds>`: 仅用于共享缓存，覆盖 `max-age`
- `no-cache`: 允许缓存存储，但必须先验证后才能使用
- `no-store`: 禁止任何缓存存储响应
- `public`: 响应可被任何缓存存储（包括共享缓存）
- `private`: 响应只能被私有缓存存储
- `must-revalidate`: 过期后必须向源服务器重新验证
- `immutable`: 表示响应永不改变（适用于带版本号的静态资源）

**请求指令**:

```http
<!-- 强制刷新：no-cache + 不带验证头 -->
Cache-Control: no-cache

<!-- 普通刷新：max-age=0 + 带验证头 → 走协商缓存 -->
Cache-Control: max-age=0
```

## 缓存判定流程图

1.  **是否有强缓存?**
    - 是 -> 检查 `max-age` 是否过期?
      - 未过期 -> **直接使用 (200 form cache)**
      - 已过期 -> 进入协商缓存阶段。
2.  **是否有协商缓存?**
    - 携带 `If-None-Match` (ETag) 或 `If-Modified-Since` (Last-Modified) 发请求给服务器。
3.  **服务器判定:**
    - 内容未变 -> 返回 **304** -> 浏览器读取本地缓存。
    - 内容已变 -> 返回 **200** + 新内容 -> 浏览器存入新缓存。

## 缓存后的请求表现 (DevTools 观察)

在 Chrome 开发者工具的 Network 面板中，我们可以通过 Status 和 Size 栏清晰地分辨出使用了哪种缓存：

| 缓存类型                | Status Code          | Size (Size / Content)                        | Time                    | 说明                                                                                                   |
| :---------------------- | :------------------- | :------------------------------------------- | :---------------------- | :----------------------------------------------------------------------------------------------------- |
| **强缓存 (命中)**       | **200 OK**           | `(from memory cache)` 或 `(from disk cache)` | **0 ms** (极快)         | 根本没有发送网络请求，直接从内存或磁盘读取。                                                           |
| **协商缓存 (命中)**     | **304 Not Modified** | Header 大小 (如 128 B)                       | **网络延迟** (如 30ms)  | 发送了请求但在服务器被拦截，服务器告诉浏览器“没变”，浏览器便去读本地缓存。节省了带宽，但仍有网络耗时。 |
| **缓存失效 / 初次加载** | **200 OK**           | 真实文件大小 (如 25 KB)                      | **下载耗时** (如 200ms) | 完整的网络请求和数据传输。                                                                             |

## HTTP 缓存 vs 浏览器缓存

| 特性         | HTTP 缓存              | 浏览器存储 (LocalStorage/IndexedDB)  |
| ------------ | ---------------------- | ------------------------------------ |
| **控制方**   | 服务器通过 HTTP 头控制 | 前端 JavaScript 完全控制             |
| **适用范围** | HTTP 请求/响应         | 任意数据                             |
| **容量**     | 浏览器自动管理         | LocalStorage ~5-10MB，IndexedDB 更大 |
| **生命周期** | 由 Cache-Control 决定  | 永久存储（除非手动删除）             |
| **跨域**     | 遵循同源策略           | 严格同源                             |

## 普通刷新和强刷的表现

- 普通刷新：
  - 浏览器会将**强缓存失效**（header 自动携带`Cache-Control: max-age=0`）。
  - 跳过强缓存，直接进入协商缓存（带上 ETag 访问服务器）。
  - 如果没变，服务器返回 304，浏览器读取本地缓存。

- 强刷：
  - 浏览器**拉取最新数据**，自动抹除所有的缓存标识（header 携带`Cache-Control: no-cache`且不带 `If-None-Match`）。
  - 服务器将其视为新请求，强制返回 200 OK 和完整文件。
