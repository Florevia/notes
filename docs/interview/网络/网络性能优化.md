# 网络性能优化体系

- **三大方面**：

  - 减少请求次数
  - 减小资源体积
  - 加快请求速度

## 减少 HTTP 请求次数

每一次 HTTP 请求都涉及 DNS 解析、TCP 握手等消耗，减少请求是降低延迟最直接的手段。

### 资源合并 (Bundling)

- 利用 **Webpack/Vite** 将多个 JS/CSS 文件合并，减少 RTT（往返时延 Round Trip Time）。

  - 注意： 控制包体大小，避免单文件过大阻塞渲染。

### 图片优化

- **雪碧图 (CSS Sprites)**：将多个小图标合并为一张大图，通过 `background-position` 定位。

- **Base64 内联**：对于极小图标（< 4KB），转为 Base64 嵌入 HTML/CSS，免去网络请求。

```css
/* 在 CSS 背景图中使用 */
.icon-loading {
  width: 16px;
  height: 16px;
  /* 非常长的一串字符，代表一个 loading 图标 */
  background-image: url("data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAQAAAC1HAwCAAAAC0lEQVR42mNk+A8AAQUBAScY42YAAAAASUVORK5CYII=");
}
```

```html
<!-- HTML 中直接使用 -->
<img
  src="data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAQAAAC1HAwCAAAAC0lEQVR42mNk+A8AAQUBAScY42YAAAAASUVORK5CYII="
/>
```

### 合理分包

- 提取 **公共代码**（CommonChunk），复用长期不变的第三方库（Vendor）。

  - 避免每次 **业务代码更新** 导致整个依赖包重新下载。

## 减小资源体积

传输的数据越少，加载越快。

### 代码压缩与摇树优化

- **Minification (代码压缩)**：移除空格、注释，缩短变量名。

  - 工具：

    - Terser (Webpack 默认集成)
    - UglifyJS (老牌)
    - esbuild (新一代，Go 写的高性能版)

  - 具体实现（AST 操作）：

    - Parse: 将源代码转换为抽象语法树 (AST)。
    - Compress: 对 AST 进行优化和转换。
      - 发现 first 变量名太长 -> 改成 a。
      - 发现空格/注释 -> AST 节点里不需要这些，直接删。
      - 发现 if(false) {...} -> 死代码，直接删节点。
    - Generate: 将优化后的 AST 转换回源代码。

```js
// 源文件
function add(first, second) {
  return first + second;
}
// 压缩后 (移除空格、换行，重命名变量)
function a(b, c) {
  return b + c;
}
```

- **Tree Shaking**：基于 ES6 Module 静态分析，在代码运行之前（打包阶段），就把没用的代码删掉。

  - 前提: 必须使用 ES6 Module (`import` / `export`)，因为它是静态结构的。CommonJS (`require`) 很难做 Tree Shaking。

### 开启服务器压缩

- 配置 **Nginx**/**Apache** 开启 **Gzip** 或 **Brotli**（压缩率比 Gzip 高 15%-20%）。

  - 什么叫服务器压缩？

    - 资源在服务端（Nginx）发出前，先用压缩算法（如 Gzip）压成 `.gz` 文件。浏览器收到二进制流后，自动解压复原。

    - 流程:

      - 浏览器: 请求头带 `Accept-Encoding`: `gzip`, `deflate`, `br`（告诉我支持解压这些格式）。
      - 服务器: 找到原文件 index.js (100KB)，压缩成二进制流 (30KB)，响应头带 `Content-Encoding`: `gzip`。
      - 浏览器: 收到 30KB，解压成 100KB 执行。

### 图片格式优化

- 优先使用 **WebP** 或 **AVIF**，同画质下体积比 JPEG/PNG 小 30%-50%。

- 使用 **SVG** 替代简单的位图图标。

  - 位图 (PNG/JPG): 也就是像素图。记录 (0,0) 是红色，(0,1) 是蓝色。图越大文件越大。

  - 矢量图 (SVG): 是一段 XML 代码。记录“画一个半径 50 的圆，颜色 #F00”。无论放大多少倍，它也就是这一行代码，体积极小且不失真。

## 优化网络传输链路

### 缩短数据传输的物理距离和逻辑链路。

- **CDN (内容分发网络)**

  - 将静态资源分发到离用户最近的边缘节点，降低物理延迟。

### 升级 HTTP 协议

- **HTTP/2**：利用 **多路复用** 解决浏览器并发限制和队头阻塞；利用 **头部压缩** (HPACK) 减小报文体积。

- **HTTP/3 (QUIC)**：基于 UDP，解决 TCP 丢包导致的队头阻塞，建立连接更快.

  - **QUIC** 是在 **UDP** 之上（应用层） 自己重新写了一套“可靠传输”的代码:

    - **QUIC** 给每个 **UDP** 包打了序号。
    - **QUIC** 也有重传机制：如果发了 1、2、3，只收到了 1、3。**QUIC** 协议栈会告诉服务器：“重传一下 2”。
    - “独立流”的好处: **TCP** 丢包会导致整个连接的所有流都停下来等（队头阻塞）。**QUIC** 丢了“图片流”的包，只会重传图片流的数据，“HTML 流”不受影响继续跑。

### DNS 预解析

- 使用 `<link rel="dns-prefetch" href="//example.com">` 提前解析后续需要的域名。

## 充分利用缓存策略

最好的网络请求就是“不发送请求”。

### 强缓存 (Strong Cache)

- **Header**：`Cache-Control: max-age=31536000`

  - 效果：资源在有效期内直接从本地（Disk/Memory）读取，状态码 200。

### 协商缓存 (Negotiated Cache)

- **Header**：`ETag` / `Last-Modified`

  - 效果：强缓存失效时询问服务器，若文件未变，返回 304，不传输 Body。

### Service Worker

- 实现离线缓存和精细化的 PWA 资源控制。

  - 拦截所有 HTTP 请求：fetch 事件中，你可以决定是从网络拿，还是从 CacheStorage 拿。

  - 即使断网（Offline），也可以返回之前缓存好的 HTML/JSON，让用户继续使用 App（离线应用/PWA 的核心）。

## 关键渲染路径与加载策略

根据用户浏览习惯，错峰加载资源。

### 懒加载 (Lazy Load)

- 针对非首屏图片、路由组件，利用 `IntersectionObserver` 滚动到可视区再加载。

```js
<img data-src="huge-image.jpg" class="lazy" src="placeholder.jpg" />

<script>
  // 1. 获取所有懒加载图片
  const images = document.querySelectorAll('.lazy');

  // 2. 创建观察器
  const observer = new IntersectionObserver((entries) => {
    entries.forEach(entry => {
      // 3. 如果进入可视区 (isIntersecting)
      if (entry.isIntersecting) {
        const img = entry.target;
        // 4. 将真实地址赋值给 src，开始加载
        img.src = img.dataset.src;
        // 5. 停止观察
        observer.unobserve(img);
      }
    });
  });

  images.forEach(img => observer.observe(img));
</script>
```

### 预加载/预获取

- Preload (`<link rel="preload">`)：高优先级加载当前页关键资源（字体、首屏大图）。

- Prefetch (`<link rel="prefetch">`)：浏览器空闲时低优先级加载下一页可能用的资源。

### SSR (服务端渲染) / SSG（静态站点生成）

- 直接返回渲染好的 HTML，减少客户端 JS 下载和执行时间，加速 FCP (First Contentful Paint)。
