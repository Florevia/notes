# 回流与重绘

## 回流 (Reflow / Layout)

当页面的几何属性（尺寸、布局、位置）发生改变，浏览器需要重新计算元素在视口内的确切位置和大小。

- **触发原因**：修改 `width`、`height`、`margin`、`padding`、`border`，增删 DOM 节点，或者获取 `offsetWidth`、`scrollTop` 等属性。

- **关键点**：回流的成本非常高，因为它会由父节点向子节点递归计算，甚至波及全局。

## 重绘 (Repaint)

当元素的外观属性（颜色、背景、可见性）发生改变，但不影响布局时，浏览器会将新样式绘制到屏幕上。

- **触发原因**：修改 `color`、`background-color`、`visibility`、`box-shadow` 等。

- **代价**：中等。不需要重新计算布局，但仍需消耗 GPU/CPU 资源。

> **注**：回流必将引起重绘，但重绘不一定引起回流。

## 现代前端开发中的优化策略

### A. 核心策略：利用 GPU 加速（复合层）

这是目前性价比最高的优化手段。

1. 使用 transform 和 opacity

   传统的 `top`/`left` 动画会触发回流，而 `transform` 和 `opacity` 的变化是在 **合成线程（Compositor Thread）** 处理的，直接由 GPU 参与，不会触发主线程的回流和重绘。

2. will-change 属性

   对于即将发生复杂变化的元素，可以使用 `will-change: transform` 提前告知浏览器将其提升为独立的合成层（Layer），但需节制使用，避免显存爆炸。

### B. 避免“布局抖动”

1. 读写分离：

   当我们连续交替 **读取布局属性**（如 `offsetWidth`、`scrollTop`）和 **设置样式** 时，浏览器为了 **返回准确的数值，会被迫强制同步刷新队列，立即执行回流**。

   优化：使用 FastDOM 库或手动将读取操作和写入操作批量分开执行。

2. React/Vue 的虚拟 DOM：

   现代框架本身就在做这件事，它们通过 Diff 算法将多次状态变更合并为一次 DOM 更新（Batch Update），极大减少了回流频率。
