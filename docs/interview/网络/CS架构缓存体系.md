# CS 架构缓存体系详解

在 CS (Client-Server) 架构中，为了提升性能、降低延迟和减少服务器压力，缓存被设计在从客户端到服务端的每一个环节中。

我们可以将其分为三层体系：**客户端层**、**网络层**、**服务端层**。

## 1. 客户端缓存 (Client Side)

离用户最近，速度最快，成本最低。

### 1.1 浏览器缓存 (Web)

- **Http 缓存**：强缓存 (`Cache-Control`) 和 协商缓存 (`ETag`)。最基础、核心的缓存。
- **本地存储**：`Cookie`、`LocalStorage`、`SessionStorage`、`IndexedDB`。用于存储 Token、用户信息或大量离线数据。
- **Service Worker**：可编程式缓存，PWA 的核心，甚至可以离线访问页面。

### 1.2 客户端应用缓存 (App/SDK)

- **磁盘文件**：App 将下载的图片、视频文件保存在手机沙盒目录中。
- **本地数据库**：如 SQLite、Realm，缓存列表数据，断网也能看旧内容。
- **DNS 缓存**：操作系统和浏览器会在本地缓存域名的 IP 地址，减少 DNS 解析时间。

---

## 2. 网络层缓存 (Network Side)

数据传输途中的缓存节点，减少回源流量。

### 2.1 CDN (内容分发网络)

- **原理**：将静态资源（图片、JS、CSS、视频）分发到全世界上千个边缘节点。用户访问最近的节点，而不是源站。
- **作用**：极大地加速了静态资源的加载，解决了跨地域访问慢的问题。

### 2.2 代理缓存 (Proxy Cache)

- **ISP 缓存**：网络运营商（电信、联通）可能会缓存热门内容。
- **企业内网代理**：公司内部网关也可以缓存常用文档或外部资源。

---

## 3. 服务端缓存 (Server Side)

最复杂的层级，通常分为三级缓存架构。

### 3.1 反向代理缓存 (如 Nginx Cache)

- **位置**：在应用服务器之前。
- **作用**：可以直接让 Nginx 缓存接口响应结果（HTML 或 JSON）。
- **适用**：读多写少、实时性要求不高的页面（如新闻列表页、详情页静态化）。

### 3.2 本地应用缓存 (Local Cache)

- **位置**：在应用进程的内存中 (JVM 堆内存)。
- **技术**：`HashMap`, `Guava Cache`, `Caffeine`, `Ehcache`。
- **特点**：速度极快（纳秒级），无网络开销。但受限于本机内存大小，且多台服务器之间数据不一致（分布式一致性问题）。

### 3.3 分布式缓存 (Distributed Cache)

- **位置**：独立部署的缓存中间件集群。
- **技术**：**Redis** (最主流), Memcached。
- **特点**：
  - **集中管理**：所有应用服务器共享同一份数据。
  - **高性能**：基于内存，QPS 极高（单机 10w+）。
  - **持久化**：支持数据落地，通过 RDB/AOF 防止丢失。

### 3.4 数据库缓存 (DB Cache)

- **Buffer Pool** (MySQL InnoDB)：数据库利用内存来缓存磁盘上的数据页和索引页，减少磁盘 I/O。
- **Query Cache**：MySQL 8.0 之前有查询缓存（SQL 语句为 key），但因命中率低已被废弃。

---

## 总结：请求流转与缓存层级

当一个请求发生时，缓存查找顺序如下：

1.  **客户端**：我有本地存过吗？(Http Cache / Storage) -> 有 -> **结束**。
2.  **DNS**：我有域名的 IP 吗？ -> 有 -> 直连 IP。
3.  **CDN**：边缘节点有这个图片吗？ -> 有 -> **结束**。
4.  **Nginx**：反向代理配置了缓存吗？ -> 有 -> **结束**。
5.  **本地缓存(App)**：JVM 内存里有这个热点数据吗？(Caffeine) -> 有 -> **结束**。
6.  **分布式缓存**：Redis 里有吗？ -> 有 -> **结束**。
7.  **数据库**：Buffer Pool 里有页数据吗？ -> 查磁盘 -> **返回并回填缓存**。
