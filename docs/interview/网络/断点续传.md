# 断点续传 (Resumable Upload/Download)

- 核心思想： **大文件分割成多个小块 (Chunks)** 进行传输。

- 主要分为 **断点下载** 和 **断点上传** 两个场景。

- 主要依赖 HTTP 协议标准中的 `Range` 和 `Content-Range` 头部。

---

## 断点下载

### 通信流程

1.  **探测文件信息 (可选)**

    - 客户端发送 `HEAD` 请求。
    - 服务端返回 `Accept-Ranges: bytes` (表示支持断点续传) 和 `Content-Length` (文件总大小)。

    ```http
    HEAD /file.zip HTTP/1.1
    Host: example.com
    ```

    ```http
    HTTP/1.1 200 OK
    Accept-Ranges: bytes
    Content-Length: 10485760
    ```

2.  **发送部分请求**

    - 客户端请求：`Range: bytes=0-1023` (请求前 1024 字节)。
    - 服务端响应：
      - `Status Code`: `206 Partial Content` (成功返回部分内容)。
      - `Content-Range`: `bytes 0-1023/10000` (当前返回范围/总大小)。
      - `Content-Length`: `1024` (当前 Body 的长度)。
      - `Body`: 二进制数据。

    ```http
    GET /file.zip HTTP/1.1
    Host: example.com
    Range: bytes=0-1023
    ```

    ```http
    HTTP/1.1 206 Partial Content
    Content-Range: bytes 0-1023/10000
    Content-Length: 1024

    [Binary Data]
    ```

3.  **续传逻辑**
    - 客户端记录已下载的字节数 (例如已下载 5000 字节)。
    - 恢复下载时，请求：`Range: bytes=5000-` (从 5000 到末尾)。

## 断点上传 (切片上传)

### 核心原理

- 切片 (Slicing)
- 索引 (Indexing)
- 合并 (Merging)

### 详细流程 (面试重点)

#### 1. 文件切片 (Client)

前端利用 `Blob.prototype.slice()` 方法（`File` 继承自 `Blob`）将大文件从逻辑上切割成多个小块。

- **注意**：`slice` 只是操作指针，不复制内存，速度极快。

```javascript
const CHUNK_SIZE = 2 * 1024 * 1024; // 2MB
const chunks = [];
let cur = 0;
while (cur < file.size) {
  chunks.push(file.slice(cur, cur + CHUNK_SIZE));
  cur += CHUNK_SIZE;
}
```

#### 2. 计算文件指纹 (Hash)

为了告诉后端“这是同一个文件的不同切片”以及“恢复上传时如何识别文件”，需要计算文件的唯一标识 (MD5)。

- **工具**: `spark-md5`。
- **优化**: 大文件计算 MD5 很慢，会阻塞主线程。**必须使用 Web Worker** 在后台线程计算，或者采用 **抽样 Hash** (取头尾+中间部分) 来牺牲少量准确性换取速度。

#### 3. 验证/秒传 (Verify)

客户端发送文件的 Hash 给服务端，询问上传状态。

**请求示例 (Request):**

```http
POST /api/upload/verify HTTP/1.1
Content-Type: application/json

{
  "fileHash": "d41d8cd98f00b204e9800998ecf8427e", // 文件的唯一标识
  "fileName": "large-video.mp4"
}
```

**响应示例 (Response):**

1.  **情况 A: 秒传 (Instant Upload)**
    服务端发现文件已存在 (Hash 命中)，直接认为上传成功。

    ```json
    {
      "code": 0,
      "shouldUpload": false, // 不需要上传
      "message": "秒传成功"
    }
    ```

2.  **情况 B: 断点续传 (Resumable)**
    服务端发现只有部分切片，返回已存在的切片 ID 列表。

    ```json
    {
      "code": 0,
      "shouldUpload": true, // 需要上传
      "uploadedChunks": [0, 1, 2], // 告诉前端：切片 0,1,2 已经有了，请从 3 开始传
      "message": "断点续传"
    }
    ```

3.  **情况 C: 新上传 (New Upload)**
    服务端完全没有记录。

    ```json
    {
      "code": 0,
      "shouldUpload": true,
      "uploadedChunks": [], // 一个切片都没有
      "message": "全新上传"
    }
    ```

#### 4. 并发上传 (Upload)

客户端根据 Step 3 的结果，过滤掉服务端已有的切片。将剩余切片封装成 `FormData`，并发上传。

- **流控 (Concurrency Control)**: 浏览器并发请求数有限 (通常 6 个)。一次性发送 1000 个请求虽然会被浏览器排队，但会占用大量内存并可能导致卡顿。推荐实现一个简单的并发调度器。

**前端代码实现 (面试加分项):**

```javascript
/* 并发控制函数
 * @param {Array<Function>} tasks - 返回 Promise 的任务生成函数数组
 * @param {number} poolLimit - 最大并发数 (如 6)
 */
async function asyncPool(poolLimit, tasks) {
  const ret = []; // 存储所有任务的 Promise
  const executing = []; // 存储正在执行的任务 Promise

  for (const task of tasks) {
    const p = Promise.resolve().then(() => task()); // 实例化 Promise
    ret.push(p); // 保存结果

    if (poolLimit <= tasks.length) {
      // 封装一下 p，执行完后从 executing 数组中移除自己
      const e = p.then(() => executing.splice(executing.indexOf(e), 1));
      executing.push(e);

      // 如果正在执行的任务达到上限，等待其中 "最早完成" 的那个任务完成
      if (executing.length >= poolLimit) {
        await Promise.race(executing);
      }
    }
  }
  return Promise.all(ret);
}
```

#### 5. 发送合并指令 (Merge)

当所有切片上传完毕后，客户端再次发送一个 `merge` 请求通知后端合并。

**请求示例:**

```http
POST /api/upload/merge HTTP/1.1
Content-Type: application/json

{
  "fileHash": "d41d8cd98f00b204e9800998ecf8427e",
  "fileName": "video.mp4",
  "size": 10485760 // 可选，用于后端校验最终大小
}
```

**响应示例:**

```json
{
  "code": 0,
  "message": "合并成功",
  "url": "https://cdn.example.com/files/video.mp4"
}
```

## 前端面试要点 (FAQ)

### Q1: 大文件上传计算 Hash 时间过长怎么办？

- **Web Worker**: 将计算密集型任务移出主线程。
- **时间切片 (Time Slicing)**: 利用 `requestIdleCallback` 空闲时计算。
- **抽样 Hash (Sample Hash)**: 不读全量文件。取文件头 2MB + 文件尾 2MB + 中间每隔 2MB 取 2KB。损失极低概率的准确性，换取 100 倍的速度提升。

### Q2: 既然 HTTP2 有多路复用，为什么还需要分片上传？

- **HTTP2 解决的是队头阻塞**，它把一个 TCP 连接复用给多个 HTTP 请求。
- **分片上传解决的是传输中断和恢复**。如果不分片，10GB 文件传到 99% 断网了，HTTP2 也得重传这 99%。分片后只需要重传失败的那几个 2MB 的切片。

### Q3: 暂停和恢复怎么做？

- **暂停**: 调用 `XMLHttpRequest.abort()` 或 `AbortController.abort()` (fetch API) 取消正在进行的请求。
- **恢复**: 重新触发上传，走“验证”流程，后端返回已上传切片列表，前端过滤后继续传剩下的。

### Q4: 很多小碎片文件会导致请求数过多怎么办？

- 限制并发数 (Concurrency Limit)。
- 切片大小动态调整：网速快时切片大一点，网速慢时切片小一点。

### Q5: 上传失败了怎么重试？

- Response 报错或超时后，不要立即失败。
- 设置重试次数 (Retry Count)，拦截器里捕获 Error 自动重新推入队列。
