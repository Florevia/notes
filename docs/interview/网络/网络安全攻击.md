# 网络安全攻击

## XSS (Cross-Site Scripting) 跨站脚本攻击

- 原理：攻击者在目标网站中注入恶意的 JavaScript 脚本。当用户浏览该网页时，脚本执行，从而窃取用户 Cookie、SessionID 或进行其他恶意操作。

- 分类：

  - 存储型 (Stored)：恶意脚本被存储在数据库中（如论坛发帖），所有查看该页面的用户都会中招。
  - 反射型 (Reflected)：恶意脚本作为 URL 参数的一部分，诱导用户点击（如邮件钓鱼）。
  - DOM 型：完全由前端 DOM 操作导致，不经过服务端（如直接取 location.search 写入 innerHTML）。

- 防御：

  - 转义/过滤：对用户输入和输出进行 HTML 转义（编码），如将 `<` 转义为 `&lt;`。
  - CSP (内容安全策略)：配置 Content-Security-Policy 响应头，限制加载外部脚本的域名，禁止行内脚本。
  - HttpOnly：设置 Cookie 的 HttpOnly 属性，禁止 JavaScript 读取 Cookie。

## CSRF (Cross-Site Request Forgery) 跨站请求伪造

- 原理：攻击者诱导受害者进入第三方网站，在第三方网站向被攻击网站发送跨站请求。利用受害者在被攻击网站已登录的凭证（自动携带 Cookie），冒充受害者执行操作（如转账、发帖）。

- 核心：攻击者无法获取 Cookie 信息，只是借用了用户的身份（Cookie）。

- 防御：

  - SameSite Cookie：设置 Cookie 的 SameSite 属性为 Strict 或 Lax，禁止/限制第三方 Cookie 发送。
  - CSRF Token：提交请求时携带一个随机生成的 Token（放在 Header 或 Body 中），服务端校验该 Token。
  - 同源检测：服务端检查 Referer 或 Origin 头，确保请求来自合法的源。

## Clickjacking - 点击劫持

- 原理：攻击者将目标网站通过 iframe 嵌入到自己的恶意网页中，并将 iframe 设置为透明。诱导用户点击恶意网页的按钮，实际上是点击了透明 iframe 中的目标网站按钮（如“关注”或“支付”）。

- 防御：

  - X-Frame-Options：设置响应头 X-Frame-Options: DENY (禁止嵌入) 或 SAMEORIGIN (同源可嵌入)。
  - JS 防御：判断 top.location 是否等于 self.location，如果不等则强制跳转。
