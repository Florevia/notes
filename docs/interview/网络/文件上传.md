# 文件上传详解

## 1. 定义

- 客户端选择文件
- 编码传输
- 服务器接收存储

文件上传主要遵循以下标准：

- **RFC 7578**: 定义了 `multipart/form-data` 媒体类型
- **HTML5 File API**: 提供客户端文件操作接口
- **FormData API**: 用于构建 multipart/form-data 格式的数据

## 2. 工作原理

### Multipart/Form-Data 格式

当使用 `multipart/form-data` 编码时，HTTP 请求体被分成多个部分，每部分由唯一的边界（boundary）字符串分隔。

**请求示例**:

```http
POST /upload HTTP/1.1
Host: example.com
Content-Type: multipart/form-data; boundary=----WebKitFormBoundary7MA4YWxkTrZu0gW
Content-Length: 12345

------WebKitFormBoundary7MA4YWxkTrZu0gW
Content-Disposition: form-data; name="username"

JohnDoe
------WebKitFormBoundary7MA4YWxkTrZu0gW
Content-Disposition: form-data; name="avatar"; filename="profile.jpg"
Content-Type: image/jpeg

[二进制图片数据]
------WebKitFormBoundary7MA4YWxkTrZu0gW--
```

**关键组成部分**:

- **Boundary**: 唯一分隔符，用于区分不同部分
- **Content-Disposition**: 描述字段名和文件名
- **Content-Type**: 指定文件的 MIME 类型
- **数据体**: 实际的文件二进制数据

## 3. 实现方式对比

### 3.1 传统表单上传

**HTML**:

```html
<form action="/upload" method="POST" enctype="multipart/form-data">
  <input type="file" name="avatar" accept="image/*" />
  <button type="submit">上传</button>
</form>
```

- **特点**:

  - 同步提交，页面会刷新
  - 无法跟踪上传进度
  - 实现简单，兼容性好

### 3.2 FormData + Fetch/XMLHttpRequest

```javascript
// 方式 1: 从表单元素创建
const form = document.querySelector("#uploadForm");
const formData = new FormData(form);

// 方式 2: 手动构建
const fileInput = document.querySelector("#fileInput");
const formData = new FormData();
formData.append("file", fileInput.files[0]);
formData.append("userId", "12345");
formData.append("description", "个人头像");

// 使用 Fetch API 上传
fetch("/api/upload", {
  method: "POST",
  body: formData,
  // 注意：不要手动设置 Content-Type，浏览器会自动添加 boundary
})
  .then((response) => response.json())
  .then((data) => {
    console.log("上传成功:", data);
  })
  .catch((error) => {
    console.error("上传失败:", error);
  });
```

### 3.3 Base64 编码上传

```javascript
function uploadImageAsBase64(file) {
  const reader = new FileReader();

  reader.onload = function (e) {
    const base64String = e.target.result; // data:image/jpeg;base64,/9j/4AAQ...

    // 发送 JSON 数据
    fetch("/api/upload-base64", {
      method: "POST",
      headers: {
        "Content-Type": "application/json",
      },
      body: JSON.stringify({
        filename: file.name,
        content: base64String,
        userId: "12345",
      }),
    })
      .then((response) => response.json())
      .then((data) => console.log("上传成功:", data));
  };

  reader.readAsDataURL(file); // 读取为 Base64
}

const fileInput = document.querySelector("#fileInput");
fileInput.addEventListener("change", (e) => {
  uploadImageAsBase64(e.target.files[0]);
});
```

### 3.4 分块上传（Chunked Upload）

适用于大文件上传，将文件分成多个小块逐个上传。

```javascript
async function uploadLargeFile(file) {
  const CHUNK_SIZE = 5 * 1024 * 1024; // 5MB per chunk
  const totalChunks = Math.ceil(file.size / CHUNK_SIZE);
  const uploadId = generateUniqueId(); // 生成唯一上传标识

  for (let chunkIndex = 0; chunkIndex < totalChunks; chunkIndex++) {
    const start = chunkIndex * CHUNK_SIZE;
    const end = Math.min(start + CHUNK_SIZE, file.size);
    const chunk = file.slice(start, end);

    const formData = new FormData();
    formData.append("file", chunk);
    formData.append("chunkIndex", chunkIndex);
    formData.append("totalChunks", totalChunks);
    formData.append("uploadId", uploadId);
    formData.append("filename", file.name);

    try {
      const response = await fetch("/api/upload-chunk", {
        method: "POST",
        body: formData,
      });

      const result = await response.json();
      console.log(`上传进度: ${chunkIndex + 1}/${totalChunks}`);

      // 如果是最后一块且服务器确认合并成功
      if (result.completed) {
        console.log("文件上传完成:", result.fileUrl);
      }
    } catch (error) {
      console.error(`块 ${chunkIndex} 上传失败:`, error);
      // 实现重试逻辑
      chunkIndex--; // 重试当前块
    }
  }
}

function generateUniqueId() {
  return `${Date.now()}-${Math.random().toString(36).substr(2, 9)}`;
}
```

## 4. 优缺点对比

### 4.1 二进制上传 (multipart/form-data)

**优点**:

- 文件大小不增加，传输效率高
- 浏览器原生支持，兼容性好
- 适合所有文件类型和大文件
- 服务器处理简单，资源消耗低

**缺点**:

- 请求体格式复杂（包含 boundary）
- 不便于嵌入 JSON 等结构化数据
- 需要专门的解析库（如 multer）

### 4.2 Base64 编码上传

**优点**:

- 可以嵌入 JSON 格式，便于传输结构化数据
- 无需专门的文件上传库
- 适合小文件和简单场景

**缺点**:

- 文件大小增加约 33%，浪费带宽
- 编码/解码消耗 CPU 资源
- 存储在数据库会导致性能下降
- 不适合大文件（>1MB）

### 4.3 分块上传

**优点**:

- 支持超大文件上传（GB 级别）
- 断点续传，网络中断后可恢复
- 降低服务器内存压力
- 更好的进度跟踪

**缺点**:

- 实现复杂，需要维护上传会话
- 服务器需要额外逻辑合并块
- 增加服务器存储开销（临时块文件）

## 5. 适用场景

### 5.1 传统表单上传

- **场景**: 简单的个人资料头像上传、文档提交
- **特点**: 小文件、低频操作、对用户体验要求不高

### 5.2 FormData + Ajax 上传

- **场景**: 现代 Web 应用的标准上传方式
- **特点**:
  - 需要进度提示的场景
  - 无刷新体验
  - 多文件上传
  - 图片预览后上传

### 5.3 Base64 上传

- **场景**:
  - 小图标、头像（<100KB）
  - 需要与其他 JSON 数据一起提交
  - 图片编辑器（如裁剪后上传）
- **限制**: 不适合大文件

### 5.4 分块上传

- **场景**:
  - 视频文件上传（>100MB）
  - 大型文档、压缩包
  - 网络不稳定的环境
  - 云存储服务（AWS S3、阿里云 OSS）

### 5.5 流式上传

- **场景**:
  - 实时音视频流上传
  - 日志文件持续上传
  - WebSocket 文件传输
