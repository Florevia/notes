# HTTP 演进

## 第一阶段：起步与确立 (HTTP/0.9 & HTTP/1.0)

这一阶段主要确立了 Web 通讯的基础模式。

- **HTTP/0.9**：
  - 极简：只有 GET 命令，没有 Header，只能传输 HTML 字符串。
  - 特点：用完即关，非常原始。

- **HTTP/1.0**：
  - 确立协议：引入了 **Header（头信息）**、**Status Code（状态码）**、**MIME Type（多媒体支持，能传图片了）**。
  - 痛点：**短连接 (Short Connection)**。每一次请求都需要进行 TCP 三次握手，传输完立即断开（四次挥手）。这对性能是巨大的浪费，因为 TCP 握手是有延迟的（慢启动）。

## 第二阶段：持久化与标准化 (HTTP/1.1)

这是互联网最长寿的版本，至今仍是主流之一。它主要是为了解决 1.0 连接复用的问题。

**核心改进：**

- **长连接 (Keep-Alive)**：默认开启。同一个 TCP 连接可以被后续请求复用，大幅减少了握手开销。
- **管道化 (Pipelining)**：试图解决并发问题。
  - **原理**：允许客户端在收到上一个请求的响应之前，发送下一个请求。

  - **痛点**：此方案并未彻底解决**队头阻塞 (Head-of-Line Blocking)**。
    因为 HTTP/1.1 规定，服务器必须**按照请求接收的顺序**来发送响应。如果第一个请求处理很慢，后面的请求即使处理完了，也必须在缓冲区排队等待第一个响应发完才能发。
  - _现状_：几乎废弃，现代浏览器默认关闭。

- **缓存控制**：引入了 Etag、Cache-Control 等更完善的缓存机制。
- **Host 头**：允许一台服务器托管多个域名（虚拟主机）。

**痛点：**

- **并发限制**：浏览器对同一个域名的 TCP 连接数有限制（通常 6 个）。
- **队头阻塞**：同一连接内的请求必须 **串行** 返回，前一个慢，后一个就得等。

## 第三阶段：性能革命 (HTTP/2)

**核心改进：**

- **二进制分帧**：将 HTTP 报文切分成更小的 **二进制帧**，机器解析更高效，也为多路复用打下基础。
- **多路复用 (Multiplexing)**：这是最重要的特性。在一个 TCP 连接中，可以 **同时** **双向** 发送多个流（请求/响应），彻底解决了 HTTP 应用层的队头阻塞。
- **头部压缩 (HPACK)**：解决了 Header 冗余传输的问题，减少流量。
- **服务端推送**：服务器可以预判并主动发送资源给客户端（虽然实际应用场景有限，目前甚至有废弃趋势）。

**痛点：**

- **TCP 队头阻塞**：虽然应用层不堵了，但底层还是 TCP。一旦发生丢包，TCP 协议栈会暂停整个连接的交付，导致所有流受牵连。在弱网环境下，HTTP/2 表现可能不如 HTTP/1.1。

## 第四阶段：底层重构 (HTTP/3)

为了解决 TCP 协议本身的限制，Google 搞出了 QUIC，进而推动了 HTTP/3。

**核心改进：**

- **拥抱 UDP**：基于 UDP 实现了 QUIC 协议，自己实现了可靠传输和拥塞控制。
- **彻底解决队头阻塞**：流（Stream）之间真正独立。丢包只影响那个特定的流，**不会影响其他流**。
- **更快的建连**：整合了 TLS 1.3，支持 0-RTT（首次连接 1-RTT，后续 0-RTT），握手速度极快。
- **连接迁移**：使用 **Connection ID** 标识连接，网络从 WiFi 切到 4G，连接不断，体验平滑。
