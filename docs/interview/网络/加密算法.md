# 加密算法

## 对称加密 (Symmetric Encryption)

**最传统、最基础的加密方式**

- 原理： 加密和解密使用同一个密钥 (Key)。

- 常见算法： AES (目前最主流、安全)、DES (已被淘汰)、3DES。

- 优点： 速度快，计算量小，适合加密大量数据。

- 缺点： 密钥管理难。必须把密钥告诉对方才能解密，但在网络传输中把密钥发给对方很容易被截获。

## 非对称加密 (Asymmetric Encryption)

**现代网络安全的基石**

- 原理： 有一对密钥：公钥 (Public Key) 和 私钥 (Private Key)。

  - 公钥加密，私钥解密： 用于传输敏感信息（别人用你的公钥锁住信件，只有你能用私钥打开）。
  - 私钥签名，公钥验签： 用于身份认证（证明这封信确实是你写的）。

- 常见算法： RSA (最经典)、ECC。

- 优点： 安全性高，解决了密钥传输问题（公钥可以随便公开）。

- 缺点： 速度极慢，计算复杂，不适合加密大文件。

## 哈希加密 (Hash Encryption)

**不可逆**

- 原理： 将任意长度的数据，映射为固定长度的字符串（特征码）。

- 特性：

  - 单向性： 无法通过 Hash 值推导出原文。
  - 抗碰撞： 不同的输入很难生成相同的输出。

- 常见算法： MD5 (不安全，仅用于校验)、SHA-256 (目前主流)。

- 前端应用场景：

  - 密码存储： 数据库里永远不要存明文密码，要存 Hash 值（加盐 Salt）。
  - 文件完整性校验： 前端 Webpack 打包后的文件名 hash (main.a1b2c3.js)，或者 SRI (Subresource Integrity) 校验。

## 在 Web 中的综合应用 (HTTPS)

HTTPS 就是这三者的完美结合：

- 非对称加密 (RSA)：用于在握手阶段，客户端和服务端安全地协商出一个“会话密钥”。
- 对称加密 (AES)：一旦有了会话密钥，后续的所有 HTTP 数据传输都用 AES 加密，保证速度。
- 哈希算法 (SHA)：用于数字证书的签名校验，确保数据没有被篡改。

这也是为什么 HTTPS 既安全（非对称）又快（对称）的原因。

## 各自必要性

- AES：

  - 处理大数据流的唯一选择。它的计算速度比非对称加密快 1000 倍 以上，且占用 CPU 资源极低。

- RSA：

  - 为了安全地告诉对方“暗号”（对称密钥），以及证明“我是我”（数字签名）

- SHA/MD5：
  - 防篡改： 下载文件时，只要对比 Hash 值，就知道文件有没有被黑客偷偷改过一个字节。
  - 存密码： 即使是系统管理员，也不应该知道用户的明文密码。
