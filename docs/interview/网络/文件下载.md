# 文件下载详解 (Frontend Interview Guide)

## 1. 核心原理

文件下载的本质是 **服务器返回特定响应头，告诉浏览器“这是一个需要保存的文件，而不是直接展示的内容”**。

核心 HTTP 响应头：

```http
Content-Disposition: attachment; filename="filename.ext"
Content-Type: application/octet-stream
```

- `Content-Disposition: attachment`: 明确触发“下载”行为。如果是 `inline`（默认值），浏览器会尝试直接打开（如 PDF、图片）。
- `filename`: 指定下载保存时的默认文件名。

---

## 2. 常见实现方式

### 方式一：a 标签 `download` 属性 (最简单)

适用于 **同源** 的静态文件。

```html
<!-- 浏览器会自动解析文件名 -->
<a href="/files/report.pdf" download="my-report.pdf">下载报表</a>
```

- **优点**：简单，HTML 原生支持。
- **缺点**：
  - **跨域限制**：如果 `href` 是跨域 URL，某些浏览器会忽略 `download` 属性，直接打开文件而非下载。
  - **无法鉴权**：GET 请求，无法自定义 Header（如 Token）。

### 方式二：`window.open` 或 `location.href`

适用于 **后端控制下载** 的简单场景。

```js
// 简单粗暴，相当于在地址栏输入 URL
window.location.href = "https://api.example.com/download/123";
```

- **特点**：完全依赖后端返回 `Content-Disposition: attachment`。如果后端没设这个头，浏览器可能会直接打开图片或 JSON。
- **缺点**：同样无法鉴权（Token 只能拼在 URL 参数里，不安全）。

### 方式三：Ajax + Blob (最常用，支持鉴权)

适用于 **需要 Header 鉴权** 或 **动态生成内容** 的场景。这是前端面试的重点。

**代码实现 (通用封装)**：

```js
async function downloadFile(url, fileName) {
  try {
    // 1. 发起请求 (可以带 Authorization Header)
    const response = await fetch(url, {
      method: "GET",
      headers: {
        Authorization: "Bearer " + localStorage.getItem("token"),
      },
    });

    if (!response.ok) throw new Error("Network error");

    // 2. 获取 Blob 二进制数据
    const blob = await response.blob();

    // 3. 创建临时下载链接
    const objectUrl = window.URL.createObjectURL(blob); // 关键！

    // 4. 构建隐藏的 a 标签触发下载
    const a = document.createElement("a");
    a.style.display = "none";
    a.href = objectUrl;
    a.download = fileName || "download.bin"; // 指定文件名
    document.body.appendChild(a);

    a.click(); // 触发点击

    // 5. 清理资源 (避免内存泄漏)
    document.body.removeChild(a);
    window.URL.revokeObjectURL(objectUrl);
  } catch (err) {
    console.error("Download failed:", err);
  }
}
```

- **原理**：先用 JS 把文件流下载到内存 (Blob)，再通过 `URL.createObjectURL` 生成一个指向内存数据的 `blob:` 协议链接，最后用 `<a>` 标签模拟点击。
- **优点**：
  - Header 里可以带 Token。
  - 可以捕获下载接口的错误（404、500）。
- **缺点**：
  - **内存占用**：文件必须全部下载到内存才能保存，下载 **超大文件** (如 1GB 视频) 会导致浏览器崩溃 (OOM)。

### 方式四：纯前端生成文件 (无后端)

适用于导出简单的 CSV、JSON、txt。

```js
const data = JSON.stringify({ name: "Alice", age: 18 });
const blob = new Blob([data], { type: "application/json" });
const url = URL.createObjectURL(blob);

// 接下来用 a 标签下载 (同上)
```

## 3. 面试高频问题 (FAQ)

### Q1: 如何处理大文件下载 (> 1GB)？

- **不要用 Ajax + Blob**，因为内存存不下。
- **方案**：直接使用 **StreamSaver.js** (利用 ServiceWorker) 或者回归原始的 `window.location.href` (浏览器自带的下载管理器会自动分片写入硬盘，不占内存)。
- 如果要鉴权且必须用 JS：
  - 方案 A: 拿着 Token 换取一个短时有效的 `download_token`，然后拼接到 URL 参数里用 `location.href` 下载。
  - 方案 B: 使用 Fetch 的 `ReadableStream` 配合 `Streams API` 逐步写入磁盘 (File System Access API, 兼容性一般)。

### Q2: 后端返回的文件名乱码怎么办？

- 通常因为 `Content-Disposition` Header 里的中文没有正确 URL 编码。
- 后端应使用 `encodeURIComponent` 编码文件名。
- 前端解码：`decodeURIComponent(filename)`.

### Q3: `Content-Disposition` 是 `inline` 和 `attachment` 的区别？

- `inline` (默认)：浏览器尝试直接渲染（PDF 在浏览器内查看）。
- `attachment`：强制弹窗保存对话框（下载）。

## 4. 总结对比

| 方式               | 鉴权支持         | 大文件支持      | 复杂度 | 适用场景                      |
| :----------------- | :--------------- | :-------------- | :----- | :---------------------------- |
| **`<a>` / `open`** | 弱 (仅 URL 参数) | **极好** (原生) | 低     | 公开文件、超大文件            |
| **Ajax + Blob**    | **强** (Header)  | 差 (OOM 风险)   | 中     | 需鉴权的 API 导出 (Excel/PDF) |
| **前端 Blob**      | N/A              | 差              | 低     | 纯前端导出 JSON/CSV           |
