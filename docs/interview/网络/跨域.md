# 跨域

## 本质

**跨域的本质是浏览器的 同源策略 (Same-Origin Policy) 限制**

- 同源的定义：协议 (Protocol)、域名 (Host)、端口 (Port) 三者必须完全一致。

- 现象：前端发出的请求发了出去，服务器也接收并处理了，但浏览器拦截了返回的响应，报 CORS error。

- 目的：为了安全，防止恶意网站通过脚本窃取其他网站的敏感数据（如 CSRF 攻击）。

## 解决跨域

### CORS 跨域资源共享（cross origin resources sharing）

- W3C 标准，主要由后端进行配置

- 原理：
  - 后端在响应头中设置 `Access-Control-Allow-Origin` 等字段，指定允许访问资源的域名。

- 关键响应头：
  - `Access-Control-Allow-Origin`: 允许的域名（如 http://localhost:8080 或 \*）。
  - `Access-Control-Allow-Methods`: 允许的方法（GET, POST, etc.）。
  - `Access-Control-Allow-Headers`: 允许的请求头（Token 等）。

- demo

```js
// 方式一：手动设置响应头
app.use((req, res, next) => {
  res.setHeader("Access-Control-Allow-Origin", "*"); // 或指定域名
  res.setHeader(
    "Access-Control-Allow-Methods",
    "GET, POST, PUT, DELETE, OPTIONS",
  );
  res.setHeader("Access-Control-Allow-Headers", "Content-Type, Authorization");
  res.setHeader("Access-Control-Allow-Credentials", "true"); // 允许携带 cookie
  next();
});

// 方式二：使用 cors 中间件：
// 自动识别请求头、自动读取前端发来的 Origin、自动设置响应头、自动处理预检
const cors = require("cors");
app.use(
  cors({
    origin: "http://my-frontend.com", // 只允许自己的前端域名
    credentials: true, // 允许携带 Cookie
    methods: ["GET", "POST"], // 只开放部分接口方法
  }),
);
```

- 简单请求和预检请求：
  - 简单请求：`GET`/`HEAD`/`POST` + `简单 Header`。
    - 直接发送请求

  - 预检请求： `PUT`/`DELETE`/`PATCH` 或`自定义 Header`
    - 浏览器会先自动发送一个 `OPTIONS` 请求（预检），询问服务器是否允许。服务器通过后，才会发送真正的请求。

### 代理服务器 (Proxy)

- 前端工程化最常用

- 本质：
  - 利用**服务器与服务器之间没有同源策略**的特点，通过中间服务器转发请求。

- 开发环境 (Dev)：
  - 使用 Webpack/Vite 的 devServer.proxy 配置。
  - 原理：前端请求发给**本地 Node.js 开发服务器**，开发服务器转发给后端。

- 生产环境 (Prod)：
  - 使用 Nginx 反向代理。
  - 配置：前端请求 /api/，Nginx 将其转发到后端真实 IP。
  - 优点：前端代码不需要改动，对浏览器透明。

```js
// vite.config.js
export default {
  server: {
    proxy: {
      "/api": {
        target: "http://backend.com",
        changeOrigin: true,
        rewrite: (path) => path.replace(/^\/api/, ""),
      },
    },
  },
};
```

```js
// vue.config.js
module.exports = {
  devServer: {
    proxy: {
      "/api": {
        target: "http://backend.com",
        changeOrigin: true,
        pathRewrite: { "^/api": "" },
      },
    },
  },
};
```

```nginx
server {
    listen 80;
    location /api {
        proxy_pass http://backend.com;
        proxy_set_header Host $host;
    }
}
```

### WebSocket

- 原理：WebSocket 协议不受同源策略限制

```js
const ws = new WebSocket("ws://other-domain.com/socket");

ws.onmessage = (e) => console.log(e.data);

ws.send("Hello");
```

### JSONP

- 利用 `<script>` 标签不受同源策略限制的特性，动态创建 script 请求

- 只支持 `GET` 请求，不安全

```js
// 前端
function jsonp(url, callback) {
  const script = document.createElement("script"); // 创建 script 标签
  // 全局注册回调函数
  window.callbackFn = (data) => {
    callback(data);
    document.body.removeChild(script); // 每次请求后移除 script 标签，防止内存泄漏
  };
  script.src = `${url}?callback=callbackFn`; // 设置 src 属性
  document.body.appendChild(script); // 将 script 标签添加到 DOM 中
}
```

### postMessage

用于解决页面和其打开的新窗口（或 iframe）之间的数据传递，通常用于多窗口通信或嵌入式页面。

发送方

```js
const iframe = document.getElementById("myIframe");
// 语法: targetWindow.postMessage(message, targetOrigin, [transfer]);
// targetOrigin 必须指定目标域名，写 '*' 不安全
iframe.contentWindow.postMessage(
  { type: "LOGIN_SUCCESS", token: "123" },
  "http://b.com",
);
```

接收方

```js
window.addEventListener("message", (event) => {
  // 1. 安全检查：必须判断发送方是谁
  if (event.origin !== "http://a.com") return;

  // 2. 处理数据
  const { type, token } = event.data;
  if (type === "LOGIN_SUCCESS") {
    console.log("收到 Token:", token);
  }
});
```
