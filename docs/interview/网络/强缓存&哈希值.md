# 在强缓存生效的情况下保证用户获取到最新资源

## 组合拳

核心策略只有一句话：
“当资源内容发生变更时，更改该资源的 URL。”

### 文件名哈希 (Content Hash) —— 最推荐方案

这是目前 Webpack、Vite 等构建工具的标准做法。

- 原理：在打包构建时，根据文件内容生成唯一的哈希值（Hash/Fingerprint），并将其嵌入到文件名中。
  - 旧版本：main.a1b2c.js
  - 修改代码后：main.x9y8z.js

- 效果：只要文件内容有一丁点改变，文件名就会变。浏览器看到的是一个新的 URL，自然会发起新请求并缓存下来.

### 入口文件 (HTML) 走协商缓存

这是配合上述 Hash 方案的关键。

- 问题：CSS/JS 文件名变了，浏览器怎么知道？
  - 是因为 HTML 文件里引用的标签 `<script src="...">` 变了。

- 策略：HTML 文件本身不设置强缓存（或者设置极短的强缓存）。
  - 通常对 index.html 设置 `Cache-Control: no-cache`。

- 这意味着浏览器每次访问 HTML 都要去服务器验证（协商缓存）。一旦发布新版，服务器返回新的 HTML（状态码 200），新的 HTML 里指向了带新 Hash 的 CSS/JS，从而触发资源更新。

## 总结

现代前端的最佳实践是：

1. **HTML (入口)**：使用 **协商缓存 (Cache-Control: no-cache)**，确保每次都拿最新的引用地址。

2. **JS/CSS/Image (静态资源)**：使用 **强缓存 (max-age=1年) + Content Hash 文件名**，确保内容变了 URL 就变，内容不变就永久缓存。
