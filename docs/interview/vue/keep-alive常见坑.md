# keep-alive

## 概念

在 Vue 中，`<keep-alive>` 是一个非常强大的内置组件，用于缓存组件实例。

但在实际项目（尤其是复杂业务）中，它经常会引发一些让人困惑的“副作用”。

## 坑点

### 1. 生命周期钩子不执行

- 现象：当你切回缓存的页面时，`created`、`mounted` 等生命周期钩子不会再次触发。

- 异常后果：如果你在 `mounted` 里请求数据或初始化图表，切回来时数据不会更新，图表可能因为容器尺寸变化而显示异常。

- 解决方案：
  - 使用专用的钩子：`activated`（被激活时触发）和 `deactivated`（被停用时触发）。

  - 将需要重置或更新的逻辑从 `mounted` 移至 `activated`。

### 2. 内存泄漏

- 现象：用户在多个详情页之间切换，每一个详情页都被缓存了。

- 异常后果：随着页面访问增多，浏览器占用的内存线性增长，最终导致页面卡顿甚至崩溃。

- 解决方案：
  - 限制缓存数量：使用 `max` 属性，例如 `<keep-alive :max="10">`。

  - 按需缓存：利用 `include` 和 `exclude` 动态控制哪些页面需要缓存。

```js
<keep-alive :max="10">
  <router-view></router-view>
</keep-alive>
```

### 3. 滚动位置丢失

- 现象：用户在一个长列表页面滚动到 `1000px`，点击进入详情页，返回时列表回到了顶部。

- 异常原因：Vue 缓存了组件实例，但对于页面级的滚动（window scroll），它并不会自动保存。

- 解决方案：
  - 在 `deactivated` 钩子中记录当前的 `scrollTop`。
  - 在 `activated` 钩子中手动将 `scrollTop` 恢复回去。
