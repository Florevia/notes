# Vue 2 和 Vue 3 生命周期对比

## 钩子对照表

| 阶段         | Vue 2（选项式） | Vue 3（组合式）           | 执行时机                                                             | 典型用途                             |
| :----------- | :-------------- | :------------------------ | :------------------------------------------------------------------- | :----------------------------------- |
| **创建前**   | `beforeCreate`  | ❌ 不需要（`setup` 替代） | 实例初始化后，数据观测和事件配置之前                                 | Vue 2 中极少使用                     |
| **创建后**   | `created`       | ❌ 不需要（`setup` 替代） | 实例创建完成，数据观测/计算属性/方法/watch 已配置好，但 DOM 还没挂载 | 发请求（但推荐 mounted）             |
| **挂载前**   | `beforeMount`   | `onBeforeMount`           | 模板编译完成，即将挂载到 DOM                                         | 几乎不用                             |
| **挂载后**   | `mounted`       | `onMounted`               | DOM 已挂载完成，可以访问 DOM 元素                                    | **发请求、操作 DOM、初始化第三方库** |
| **更新前**   | `beforeUpdate`  | `onBeforeUpdate`          | 数据变化后，DOM 更新之前                                             | 获取更新前的 DOM 状态                |
| **更新后**   | `updated`       | `onUpdated`               | DOM 已重新渲染完成                                                   | 操作更新后的 DOM（避免在此改数据）   |
| **卸载前**   | `beforeDestroy` | `onBeforeUnmount`         | 组件即将被销毁，实例仍然可用                                         | **清理定时器、取消订阅、解绑事件**   |
| **卸载后**   | `destroyed`     | `onUnmounted`             | 组件已被完全销毁                                                     | 最终清理工作                         |
| **缓存激活** | `activated`     | `onActivated`             | `<KeepAlive>` 缓存的组件重新激活                                     | 刷新数据                             |
| **缓存停用** | `deactivated`   | `onDeactivated`           | `<KeepAlive>` 缓存的组件被停用                                       | 暂停操作（如暂停视频）               |
| **错误捕获** | `errorCaptured` | `onErrorCaptured`         | 捕获子组件的错误                                                     | 错误边界处理                         |

---

## 父子组件的执行顺序（面试高频）

```
挂载阶段：
  父 setup → 父 onBeforeMount → 子 setup → 子 onBeforeMount → 子 onMounted → 父 onMounted

更新阶段：
  父 onBeforeUpdate → 子 onBeforeUpdate → 子 onUpdated → 父 onUpdated

卸载阶段：
  父 onBeforeUnmount → 子 onBeforeUnmount → 子 onUnmounted → 父 onUnmounted
```

> 规律：**父组件的 "before" 钩子先执行，但 "完成" 钩子要等子组件先完成。**

## setup函数中 `this= undefined`的原因

Vue 3 组件初始化的真实执行顺序：

1. 创建组件实例：Vue 内部创建了一个组件的实例对象（但这个时候它只是个空壳）。
2. 初始化 `Props` 和 `Slots`：解析外部传进来的属性和插槽。
3. 执行 `setup` 函数!!!
4. 解析 `Options API`：Vue 开始去读取你写的 `data()`、`computed`、`methods` 等选项。
5. 绑定到 `this` 上：Vue 把 `data` 里的响应式数据、`methods` 里的方法，统统代理（`Proxy`）到组件实例上，此时 `this` 才真正拥有了这些属性。
6. 而在 Vue 3 的 Composition API 中，你写的是直接执行的函数。
   - 当你在 setup 里写下 const count = ref(0) 时：Vue 立刻、马上在内存里开辟了一块空间，生成了一个响应式对象。
   - 它直接赋值给了你定义的局部变量 count。它根本不需要挂载到组件实例（this）上才能生效，它在当前函数作用域内已经是一个功能完备的响应式数据了。
