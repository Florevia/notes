在 Vue 开发中，发起网络请求最常用、也是最推荐的生命周期钩子是 `mounted`（在 Vue 3 中对应 `onMounted`）。

虽然在 `created`（Vue 3 的 `setup`）中发起请求也是极其常见的，但在综合考量下，`mounted` 是更安全、更标准的选择。

### 1. DOM 已经挂载完毕

在 `mounted` 阶段，Vue 已经将模板编译成了真实的 DOM 并插入到了页面中。

**场景**：很多时候，你的网络请求拿到数据后，**需要直接操作 DOM**，或者依赖 DOM 的尺寸。

**结论**：如果在 `created` 中发请求，由于请求是异步的，虽然大概率请求回来时 DOM 已经渲染完了，但如果请求极快（比如走了本地缓存），回调执行时 DOM 可能还没挂载，就会导致找不到 DOM 节点报错。而在 `mounted` 中则 100% 安全。

### 2. 服务端渲染（SSR）的兼容性

如果你使用了 **Nuxt.js** 等服务端渲染（SSR）技术，生命周期的执行规则会发生变化。

在 SSR 环境下，`beforeCreate` 和 `created` 会在服务端和客户端各执行一次。如果在 `created` 里发请求，会导致同一个请求被发送两次（服务器发一次，浏览器又发一次），浪费资源。

而 `mounted` 钩子只会在客户端（浏览器）执行。因此，将纯客户端的异步数据请求放在 `mounted` 中，是跨端同构应用的标准做法。

### 3. 避免阻塞首次渲染（用户体验考虑）

很多人有一个误区：认为 `created` 比 `mounted` 执行得早，所以在 `created` 里发请求，页面能更快展示数据。

> 真相：Vue 的生命周期是同步执行的，而网络请求（Ajax/Fetch）是异步的。从 `created` 到 `mounted` 之间的代码执行速度极快（通常不到 1 毫秒）。无论你在哪里发异步请求，JS 主线程都不会等你的请求回来，而是继续往下执行渲染 DOM。

结论：把请求放在 `mounted`，可以确保 Vue 先把页面的“骨架”（静态 HTML 结构、Loading 动画）快速渲染出来给用户看，然后再去后台拉取数据。这符合“渐进式渲染”的体验。
