# 生命周期中写异步函数是否阻塞组件的挂载和渲染

不会

## 重点

1. Vue 框架在执行你的钩子函数时，是同步调用的。Vue 内部并没有写 `await created()`。因此，无论你的 `created` 函数返回什么（哪怕是一个由于加了 `async` 而返回的 `Promise`），Vue 都会直接忽略它，继续往下执行渲染流程。

2. JavaScript 的 `async/await` 机制

   当你在钩子里写了 `await` 时，`await` 仅仅只会阻塞当前这个函数内部、排在它后面的代码，它绝对没有能力去阻塞整个 JavaScript 的主线程（如果能阻塞主线程，浏览器界面就卡死了）。

## 既然不阻塞，会导致什么现实问题？

因为不会阻塞渲染，所以你的组件会立刻使用 data 里的初始值（通常是空数组、空对象或 null）进行第一次渲染。

### 踩坑预警：

如果你在模板里直接写了 `{{ userInfo.name }}`，而 `userInfo` 初始值是 `null`，由于渲染没有被阻塞，页面会瞬间白屏并报错：`Cannot read properties of null (reading 'name')`。

### 正确的做法：

必须在模板中做好防御性编程，比如使用 `v-if` 或可选链 `?.`：

```html
<!-- 必须加 v-if，因为首次渲染时，请求还没回来，userInfo 是 null -->
<div v-if="userInfo">{{ userInfo.name }}</div>

<!-- 或者使用可选链 -->
<div>{{ userInfo?.name }}</div>
```

当 2 秒后 await 后面的代码执行，给 userInfo 赋了真实的值，Vue
的响应式系统会监听到数据变化，触发组件的重新渲染（Update），此时页面上才会真正显示出数据。

## 补充高级知识：Vue 3 中唯一能“阻塞”渲染的方法

如果你真的希望组件等请求拿回来之后再渲染（也就是真的阻塞挂载），在 Vue 2 中是做不到的。但 Vue 3 提供了一个新特性：`<Suspense>`。

- `<Suspense>` 是 Vue 3 内置组件，用于处理异步组件的加载状态。
- 它有两个插槽：`#default` 放异步组件，`#fallback` 放加载中的占位内容。
- 当子组件的 setup 包含顶层 `await` 或使用 `defineAsyncComponent` 时，`Suspense` 会等待异步完成后才渲染，期间展示 `fallback` 内容，避免页面闪烁。

在 Vue 3 的 `<script setup>` 中，你可以直接使用顶层 `await`：

```vue
<script setup>
// 顶层 await！这会使得整个组件的 setup 变成异步的
const res = await fetch("/api/data").then((r) => r.json());
</script>
```

```vue
import { defineAsyncComponent } from 'vue' const AsyncComponent =
defineAsyncComponent(() => import('./HeavyComponent.vue') )
```

配合父组件的 `<Suspense>`：

```vue
<Suspense>
  <!-- 默认插槽：真正要渲染的异步组件。它会被阻塞，直到内部的 await 执行完毕 -->
  <AsyncComponent />

  <!-- 具名插槽 fallback：在等待 await 的期间，页面上会显示这个 loading -->
  <template #fallback>
    <div>正在拼命加载中...</div>
  </template>
</Suspense>
```
