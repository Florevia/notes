# 组件间通信方式

## 1. 父子组件通信 (Parent-Child)

- 这是最基础且符合“单向数据流”原则的通信方式。

### Props / Emits

- Props：父传子，属于单向绑定。
- Emits：子传父，通过触发自定义事件通知父组件更新。

```js
// 父组件
<ChildComponent :propName="propValue" @custom-event="handleCustomEvent" />;

// 子组件
<template>
  <div>哦哦哦，
    {{ propName }}
  </div>
  <button @click="handleClick">Click me</button>
</template>

<script setup>
const props = defineProps({
  propName: {
    type: String,
    required: true
  }
});

const emit = defineEmits(['custom-event']);

function handleClick() {
  emit('custom-event', 'some data');
}
</script>
```

### v-model (双向绑定)

- Vue 3 中通过 `modelValue` 和 `update:modelValue` 实现的语法糖，支持多个绑定参数。

#### v-model 与 Props/Emits 的区别

本质上 `v-model` 就是 `props` + `emits` 的**语法糖**，你的直觉是对的，它们底层机制是一样的。但在开发中有所区分：

1.  **语意不同**：
    - `v-model` 强调**双向同步**，通常用于表单控件或需要“同步状态”的 UI 组件（如弹窗显示/隐藏、开关状态）。
    - `Props/Emits` 强调**单向数据流**和**事件通知**，更加通用（如点击按钮触发业务逻辑）。

2.  **代码简化**：
    - **Props/Emits 原始写法**: 需要父组件手动监听事件并更新值。
      ```html
      <Child :modelValue="count" @update:modelValue="val => count = val" />
      ```
    - **v-model 语法糖**: 自动处理监听和更新，代码更简洁。
      ```html
      <Child v-model="count" />
      ```

### Template Refs (ref)

- 父组件通过 ref 获取子组件实例，从而直接调用子组件的方法或访问其属性。

- 注意：在 `<script setup>` 中，子组件必须通过 defineExpose 显式暴露成员，父组件才能访问。

## 2. 跨层级通信 (Ancestor-Descendant)

- 当嵌套层级过深（Prop Drilling）时，使用 Props 传递会使代码难以维护。

### Provide / Inject (依赖注入)

- 原理：祖先组件定义 provide，所有后代组件都可以通过 inject 接收（核心规则：单向数据流维护）。

- 建议 provide 传递 ref 或 reactive 对象。为了遵循单向数据流，建议在 provide 端定义修改数据的方法并一并传出。

options API：

```js
// 祖先组件
export default {
  provide() {
    return {
      theme: 'dark',
      count: this.count  // 注意：这样传的不是响应式的
    }
  }
}

// 后代组件
export default {
  inject: ['theme', 'count']
  // 或者带默认值：
  // inject: {
  //   theme: { default: 'light' }
  // }
}
```

composition API:

```js
// 祖先组件
import { provide, ref } from "vue";

const count = ref(0);
const increment = () => count.value++;

provide("count", count); // 传递响应式 ref
provide("increment", increment); // 传递方法

// 后代组件
import { inject } from "vue";

const count = inject("count"); // 获取响应式 ref
const increment = inject("increment", () => {}); // 带默认值
```

### $attrs

- 包含了父作用域中不作为 prop 被识别的绑定属性。常用于二次封装第三方组件库，实现属性的“透传”。

## 3. 全局状态管理

- **Pinia** (推荐) / **Vuex** (旧版)

### 相对于事件总线 (Event Bus) 的优势

虽然事件总线很灵活，但在中大型应用中，全局状态管理（Store）是更好的选择：

1.  **可维护性与结构化**：
    - **Store**：数据集中定义，结构清晰，修改逻辑（Actions）和获取逻辑（Getters）内聚在一起。
    - **Event Bus**：数据流是“隐式”的，散落在各个组件的 `emit` 和 `on` 回调中，难以通过代码一眼看出数据全貌。

2.  **可追踪性与调试 (DevTools)**：
    - **Store**：支持 Vue DevTools，可以时光旅行（Time Travel）查看每一次状态变更记录，明确知道是“谁”在“什么时候”修改了数据。
    - **Event Bus**：完全黑盒，出现 Bug 时很难排查是哪个组件发出的事件，或者是谁在监听事件。

3.  **响应式自动更新**：
    - **Store**：数据是**响应式**的。你只需要在模板中使用 Store 的数据，当数据变化时，视图会自动更新。
    - **Event Bus**：本质是消息传递。接收方收到消息后，通常需要**手动**将数据赋值给本地变量才能触发视图更新。

4.  **避免命名冲突**：
    - **Store**：通过模块（Module）或独立的 Store ID 隔离。
    - **Event Bus**：所有事件名共享一个全局命名空间，容易发生字符串拼写错误或重名覆盖。

## 4. 全局事件总线 (Event Bus)

全局事件总线的本质是一个 **单例对象**，它在所有组件都能访问到的地方（通常是全局）维护一个事件中心，具备两个核心能力：

### 设计模式本质

发布-订阅模式 (Pub/Sub)

- **发布 (Emit)**：触发事件并传递数据。
- **订阅 (On)**：监听事件并接收数据。

### 缺点

1. **数据流向不透明**： 当项目变大，你在任何地方都能 $emit，却很难追踪是哪里触发的，导致 Debug 极其困难。这违背了“单向数据流”和“可预测性”的原则。

2. **内存泄漏风险**： 容易忘记在 beforeDestroy (或 onUnmounted) 中调用 $off 进行解绑，导致事件监听器不断堆积，造成内存泄漏。

3. **命名冲突**： 缺乏命名空间，多人协作时容易出现事件名覆盖。

### vue2到3版本演进

在 Vue 2 中，每一个 Vue 实例都内置了三个核心方法：

- `$on(eventName, callback)`：监听（订阅）事件。

- `$emit(eventName, data)`：触发（发布）事件。

- `$off(eventName)`：移除（取消订阅）事件。

```js
// main.js 安装全局事件总线
import Vue from "vue";
import App from "./App.vue";

new Vue({
  beforeCreate() {
    // 安装全局事件总线，$bus 就是当前应用的 vm
    Vue.prototype.$bus = this;
  },
  render: (h) => h(App),
}).$mount("#app");
```

```js
// A组件：发送者
export default {
  methods: {
    sendData() {
      // 触发名为 'receiveMessage' 的事件，并传递数据
      this.$bus.$emit("receiveMessage", "你好，我是来自A组件的消息！");
    },
  },
};
```

```js
// B组件：接收者
export default {
  mounted() {
    // 监听事件
    this.$bus.$on("receiveMessage", (data) => {
      console.log("B组件收到了数据：", data);
    });
  },
  // 重要：在组件销毁前解绑事件，防止内存泄漏
  beforeDestroy() {
    this.$bus.$off("receiveMessage");
  },
};
```

- Vue 3：推荐 mitt

Vue 3 移除了实例上的 `$on`, `$off` 和 `$once` 方法，因此无法像 Vue 2 那样直接使用 Vue 实例作为 Event Bus。官方推荐使用轻量级库 `mitt`。

#### 1. 安装

```bash
npm install mitt
```

#### 2. 封装 (utils/bus.js)

```js
import mitt from "mitt";

const bus = mitt();
export default bus;
```

#### 3. 使用

```js
// 发送事件 (Component A)
import bus from "@/utils/bus";

function handleClick() {
  bus.emit("foo", { a: "b" });
}

// 接收事件 (Component B)
import bus from "@/utils/bus";
import { onMounted, onUnmounted } from "vue";

// 必须在组件销毁时解绑，否则会造成内存泄漏
const handler = (e) => console.log("foo:", e);

onMounted(() => {
  bus.on("foo", handler);
});

onUnmounted(() => {
  bus.off("foo", handler);
});
```

## 推荐

| 关系类型       | 推荐方式            | 理由                               |
| -------------- | ------------------- | ---------------------------------- |
| 直接父子       | props / emits       | 最标准、易追踪的数据流。           |
| 深层嵌套       | provide / inject    | 避免多层 Prop 透传，降低耦合。     |
| 全局/多处共享  | Pinia               | 结构化存储，支持持久化和调试工具。 |
| 解耦的任意组件 | mitt 或 Composables | 适用于没有明确层级关系的逻辑联动。 |
| 二次封装组件   | $attrs              | 实现对原始属性的完美继承。         |
