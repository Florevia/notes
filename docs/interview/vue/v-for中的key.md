# v-for 中的 key

思考角度：

- 虚拟 DOM 的 Diff 算法
- 组件状态维护

## 核心作用

**Vue 虚拟 DOM 的唯一标识**

1. 在数据发生变化时，Vue 会生成新的虚拟 DOM 树，并通过 Diff 算法将其与旧的虚拟 DOM 树进行对比。key 让这个对比过程更加精准和高效：
   - （精准）精确匹配：Diff 算法通过 key 和 tag（标签名）来判断两个节点是否为同一个节点。
   - （高效）最小化 DOM 操作：有了 key，Vue 能够准确地追踪到哪些元素被移动了、哪些被删除了、哪些是新添加的。这避免了不必要的 DOM 重新渲染，从而将操作开销降至最低。

## index 弊端

- 如果用 index 做 key，当数组发生逆序删除、插入等操作时，会导致相同的 index 指向了不同的数据项。这会强制 Vue 进入‘就地复用’逻辑：
  - 性能上：它会导致大量不必要的 DOM 更新，因为 Vue 误以为节点没变，只是内容变了。

  - 正确性上：它会导致 DOM 状态（如 input 内容、CSS 动画状态）发生错位，因为 DOM 元素被复用了，但其内部持有的非响应式状态没有被重置。
