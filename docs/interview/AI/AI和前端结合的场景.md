# AI + 前端技术深度结合场景 (面试/实战总结)

## 1. B 端业务：复杂表单的“零录入”体验

**痛点是什么？**
像报销、供应链、CRM 这种 B 端系统，用户经常要对着一张发票或合同，手动把几十个字段一个个敲进去，效率很低，体验也差。

**我的方案：**
用**多模态大模型**直接"看图识字"，一步到位提取结构化数据。

**具体怎么做的？**

1. 用户把发票、合同这些文件拖进来
2. 前端把文件转成 Base64，调 GPT-4o 这类多模态 API
3. Prompt 里开启 **JSON Mode**，让 AI 严格按我们表单的 Schema 输出
4. 拿到 JSON 后，直接 `form.setValues(data)` 一键填充

**一个关键细节：**
AI 识别不是 100% 准的，所以我做了个**置信度校验**——AI 不确定的字段会在 UI 上标红高亮，强制让用户确认一下。这就是"人机协同"（Human-in-the-loop）的思路。

---

## 2. BI 数据可视化：自然语言生成图表

**痛点是什么？**
传统 BI 仪表盘太难用了，用户想看个数据得点好几个下拉框、勾选一堆筛选条件，门槛很高。

**我的方案：**
让用户直接用自然语言描述需求，AI 自动生成图表配置（我叫它 **Text-to-Config**）。

**具体怎么做的？**

1. 给用户一个输入框，直接打字，比如"对比 Q1 和 Q2 华东区的销售增长"
2. 关键点：AI 不是生成图片，而是生成 **ECharts/AntV 的配置 JSON**
3. 前端拿到配置后，直接 `<ECharts option={aiResponse} />` 渲染出来

**两个关键细节：**

1. **防止 AI 幻觉**：Prompt 里要注入当前数据集有哪些字段，不然 AI 可能编造不存在的字段名
2. **错误兜底**：万一 AI 返回的配置格式有问题，要捕获异常并展示降级 UI

---

## 3. C 端交互：生成式 UI (Generative UI)

**痛点是什么？**
很多聊天助手都只返回干巴巴的文字。但用户想买东西、选座、看商品时，光看文字根本不够用，体验很割裂。

**我的方案：**
用 **Generative UI**。简单说，就是 AI 觉得该展示界面的时候，前端就渲染一个真实的交互组件，而不是 Markdown 文本。

**具体怎么做的？**

1. **意图识别**：比如用户说"我想买个手机"，AI 触发 Function Calling (`get_products`)
2. **组件挂载**：前端拦截到这个 Function 调用结果，不渲染文本，而是去加载对应的 React/Vue 组件（比如 `<ProductCardList />`）
3. **混合渲染**：最终用户的聊天窗口里，既有文字回复，又穿插着可以点击交互的商品列表

**技术难点：**
这里处理 **Streaming 流**会比较麻烦，需要把文本流和 UI 组件流混合在一起渲染，一般会配合 Vercel AI SDK 或 RSC 来做。

---

## 4. 极致隐私：纯浏览器端离线推理

**痛点是什么？**
有些功能像图片去背景、合同脱敏，用户很在意隐私，根本不想把文件传到服务器上；或者为了符合 GDPR 这种合规要求。

**我的方案：**
直接在浏览器里跑模型，**数据完全不出用户电脑**。技术上就是 WASM + WebGPU。

**具体怎么做的？**

1. 用 `Transformers.js` 把轻量级模型下载下来，存到浏览器缓存（IndexedDB）里
2. 开一个 **Web Worker** 线程，利用 **WebGPU** 加速计算，防止卡死主线程
3. 直接在本地算出结果

**这有什么好处？**
除了隐私安全，还没网也能用（离线可用），而且帮公司省了服务器算力钱，因为用的是用户自己的显卡。

---

### 💡 资深视角的总结

我觉得这波 AI 浪潮对前端的影响是本质性的：

1. **交互变了**：以前是点鼠标，以后是说话（自然语言意图）
2. **逻辑变了**：以前是写死的 `if-else`，现在是概率性的模型推理
3. **界面变了**：以前是设计好的静态页面，以后可能是 AI 现场生成的 UI
4. **算力变了**：前端不再只是展示，还得利用 WebGPU 帮服务器分担算力压力
