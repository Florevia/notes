# RAG 模型

## 必要性

如果不使用 RAG，让大语言模型（LLM）回答问题就像是 **闭卷考试**，它只能依靠训练时记忆的知识，不仅容易过时，还可能为了掩盖知识盲区而出现幻觉。

而 RAG 则是给模型提供了一次 **开卷考试**的机会，让它先去翻阅最新的、私有的参考资料，然后再结合资料给出严谨的答案。

## 核心原理

RAG 的核心思想是将 **信息检索（Retrieval）与文本生成（Generation）** 结合起来。它不改变 LLM 的底层权重（不重新训练模型），而是通过在外部知识库中寻找与用户提问最相关的内容，将其作为上下文（Context）拼接在提示词（Prompt）中，喂给大模型。

## 工作流程

RAG 的完整工作流通常分为两个独立运作的阶段：

- 离线数据准备阶段
- 在线检索生成阶段

### 阶段一：离线数据准备

这个阶段的任务是：

把各种格式的文档转化为机器能够理解和快速检索的数据结构。

1. 数据提取与解析： 将企业或个人的外部数据（PDF、Word、Markdown、HTML 等）解析提取为纯文本。

2. 文本分块（Chunking）： 大模型有上下文长度限制，且整篇文档直接匹配的精确度很低。因此需要将长文本切割成包含语义的短文本块（Chunk）。切分策略通常按 **段落、特定长度（如 500 个字符）或特定的语义符号**（如换行符）进行。

3. 向量化（Embedding）： 这是 RAG 的关键。使用 `Embedding 模型` 将每一个文本块转换为向量。语义相近的文本，其向量在空间中的距离就越近。

4. 入库存储： 将 **生成的向量数据以及对应的原文片段** 存储到专门的向量数据库中，并建立索引以备后续的高效检索。

### 阶段二：在线检索与生成

当用户在前端聊天框中输入一个问题时，系统会执行以下步骤：

1. 用户查询向量化： 使用与阶段一完全相同的 `Embedding 模型`，将用户的提问转化为一个高维向量。

2. 相似度检索： 将用户查询的向量拿到向量数据库中进行比对。(最常用的数学比对方法是余弦相似度)。数据库会返回相似度最高的前 K 个（Top-K）文本块。

3. 构建 Prompt（提示词工程）： 将检索出来的 Top-K 文本块作为“参考背景”，与用户原始的提问拼接在一起。通常会使用一个标准的模板。
   > 例如：“请你根据以下参考资料回答用户的提问。如果参考资料中没有相关信息，请回答‘我不知道’。参考资料：[检索出的 Chunk 1] + [检索出的 Chunk 2]用户提问：[用户的原始问题]”
4. 大模型生成回复： 将拼接好的 Prompt 发送给 LLM。LLM 读取参考资料，提取关键信息，并用自然流畅的语言生成最终答案，通常会通过 Server-Sent Events (SSE) 流式传输回前端展示。
