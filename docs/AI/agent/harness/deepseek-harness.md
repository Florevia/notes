# Deepseek 架构详解

## 概念

DSH（DeepSeek Harness）是一套以插件系统为底座、以事件化会话为状态核心、以 Agent Loop 为执行引擎的智能体运行环境。

## 整体架构

```mermaid
┌────────────────────────────────────────────────────────────────────┐
│                         使用入口 / 应用表层                          │
│          Web GUI          Headless          SDK          ACP       │
└──────────────────────────────┬─────────────────────────────────────┘
                               │
┌──────────────────────────────▼─────────────────────────────────────┐

┌──────────────────────────────▼─────────────────────────────────────┐

│  Agent / Inbox       Agent Loop       System Prompt      LLM 路由   │
```

理解整套架构，可以抓住四条主线：

组合主线：这个应用由哪些插件组成？
执行主线：一次用户请求如何变成模型调用和工具操作？
状态主线：发生过什么，怎样保存、恢复和重建？
控制主线：哪些操作允许执行，怎样取消、审批和限制？

## 启动架构

一个Launcher，多种profile

1. dsh 是统一启动器

DSH 没有为 Web、SDK、ACP 各自维护一套互不相关的核心程序，而是使用同一个启动器，选择不同的 Profile。

例如： 

```bash
dsh web
dsh --profile headless "运行测试并总结结果"
dsh --profile sdk
dsh --profile acp
```

2. Profile 本质上是“插件组合配方”

一个 Profile 主要指定：

- 安装了哪些插件包
- 启用了哪些 Bundle
- 对默认组合做了哪些覆盖

其中，Bundle 更像预制配置包，而不是一个巨型服务。例如 dsh-base 本身主要是一份静态 patch：把模型、会话、工具和安全策略等插件插入配置树。

3. 配置按层叠加

```
空配置根
    │
    ▼
Bundle A 的 Patch
    │
    ▼
Bundle B 的 Patch
    │
    ▼
Profile 级用户 Patch
    │
    ▼
Home 级用户 Patch
    │
    ▼
命令行 --patch 覆盖
    │
    ▼
最终插件配置树
```


## Cordis：DSH 的“运行时骨架”

DSH 的模块化不是简单地把代码拆成很多 npm 包，而是建立在 Cordis 插件框架之上。

它主要提供五种机制：

| 机制 | 在 DSH 中的意义 |
| --- | --- |
| `Context` | 插件访问服务、注册事件和能力的上下文 |
| `Service` | 提供可注入的公共能力，如会话、工具、模型服务 |
| 依赖注入 | 服务存在后才激活消费者，避免手动维护启动顺序 |
| `Fiber` / 生命周期 | 跟踪插件拥有的资源，卸载时清理 |
| 事件与流水线 | 在执行关键节点上允许策略和扩展介入 |

可以把它理解为：

> 依赖注入容器 + 插件生命周期管理器 + 事件协作系统。

例如，一个工具插件不必直接依赖某个具体文件系统实现，而是消费文件系统服务。部署时可以提供本地实现，也可以提供带策略约束的实现。

## 四、Agent 核心：谁保存状态，谁负责执行？

这几个概念需要分开：

| 概念 | 职责 | 不应混同为 |
| --- | --- | --- |
| `Session` | 保存事件事实，派生模型历史 | 正在运行的大模型 |
| `Agent` | 会话的运行实体，具有输入、状态和取消能力 | 一份静态聊天记录 |
| `Agent Loop` | 驱动模型请求、工具执行、下一步循环 | 模型提供方 |
| `System Prompt` | 组装提示词、动态上下文和可见工具 schema | 单个固定字符串 |
| `LLM 服务与适配器` | 路由模型请求，适配提供方协议与能力 | 整个 Agent |
| `Tool Runtime` | 注册、解析、约束并执行工具调用 | 直接执行模型输出 |
